# M99 - Release-Candidate Validation Rehearsal

**Status:** Planned. Quality label: `stabilization`.

## Agent Start Prompt

Read M77-M98 and all current validation artifacts. Run preflight. Rehearse
M100 without adding feature breadth.

## Goal

Freeze the M100 runbook, evidence locations, and blocker list.

## Scope

- Run candidate cargo baseline, focused harness groups, vanilla oracle
  scenarios, real-client pack, performance matrix, concurrency matrix,
  crash/restart scenarios, autoscale soak, and coverage accounting.
- Re-run the generated-world join/chunk-stream scenario from M91: Solaris
  empty-world generation, restart/open, long `wire-probe` or real-client
  join at view distance 8, and full-window stream metrics. The runbook must
  compare against the M77 baseline of 289/289 chunks in 17.3s with tick and
  `chunk_prepare` warnings.
- Produce a draft M100 report with blockers, degraded gates, accepted
  divergences, non-goals, and known manual/client failures.
- Fix flakes only if they are validation infrastructure bugs; product bugs
  become M97-style blockers or M100 blockers.

## Acceptance

- M100 has a concrete runbook and expected artifact paths.
- Flakes are fixed, quarantined with reason, or listed as blockers.
- Generated-world performance/concurrency evidence has explicit artifact
  paths and is green, owner-accepted degraded, or listed as an M100 blocker.
- Owner can decide whether M100 is likely `release-ready` or only
  `stabilization`.
