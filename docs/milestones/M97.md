## Implementer 20/20 slice - generated-world blocker guard

Evidence source: M77 and the validation ledger rows C1, C2, O1, and O2
recorded a concrete generated-world blocker: a view-distance-8 spawn
window streamed all 289 chunks but took 17.3s and emitted tick,
`chunk_prepare`, and `save_all_flush` warnings.

This slice does not claim the blocker is fixed. It tightens the focused
chunk-stream regression so it exercises the same 289-chunk view-distance-8
window as `example.toml` and the M77 blocker instead of the previous
441-chunk view-distance-10 mismatch. The sidecar-dependent guard is ignored
by default so the normal cargo baseline does not fail on gitignored local
vanilla data. Run it explicitly with
`cargo test -p mc-test-harness --test chunk_stream vanilla_client_receives_spawn_view_distance_window -- --ignored --nocapture`.
That explicit guard requires both `data/vanilla/reports/blocks.json` and
`data/vanilla/reports/block_light.json`, asserts the in-memory generated
stream exercised chunk CPU pipeline metrics, and checks IO/CPU resource
metrics against the configured `ChunkPipelinePolicy`. That protects the
bounded worker ownership and light-path guard claim only; M99/M100 still need
fresh disk-backed latency, tick, lock, and flush evidence for the M77 blocker.
