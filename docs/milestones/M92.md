# M92 - Autoscale And Runtime Control Plane

**Status:** Planned. Quality label: `draft`.

## Agent Start Prompt

Read M77-M91, performance evidence, runtime config, and operator docs.
Run preflight. Add operational autoscale primitives for weak and strong
machines.

## Goal

Make Solaris degrade predictably on weak hardware and use strong hardware
without hiding lock bottlenecks.

## Scope

- Profiles: `low_end`, `balanced`, `high_end` for workers, view/sim
  distance, queues, caches, compression, chunk-send budgets, save cadence.
- Runtime controller: dynamic chunk load/generate/send budgets based on
  tick time, queue depth, memory pressure, worker saturation, first chunk
  SLA.
- Health/status output, graceful drain, load shedding, slow-client policy,
  safe config reload where feasible.
- Shared-world horizontal sharding is non-goal unless a later ADR designs
  it; independent instances behind proxy/lobby are allowed.

## Acceptance

- Autoscale decisions are observable and hysteresis prevents oscillation.
- Low-end profile degrades view/throughput predictably, not correctness.
- High-end profile improves throughput or identifies exact lock blockers.
