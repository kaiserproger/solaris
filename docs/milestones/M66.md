# M66 - Remaining simple plant lifecycle

**Status:** Closed locally; M66.a through M66.z landed. Branch:
`dev/M66-remaining-simple-plant-lifecycle`, stacked after local M65.
**Owning crates:** `mc-net` for plant lifecycle behavior and focused tests;
`docs` for readiness and closeout.

## Goal

Close a bucket of small visible plant-lifecycle gaps that can be implemented
through existing block-edit, item-drop, bonemeal, and random-tick paths without
new packet layouts or exact vanilla simulation parity.

## Scope

- Add mature melon/pumpkin stem fruit placement and attached-stem conversion
  where the needed block states are available from the registry.
- Add simple deterministic harvest behavior for already-supported mature plant
  states when it can reuse existing drops/inventory/block-edit paths.
- Tighten vertical/crop plant helpers where one shared helper can cover multiple
  simple lifecycle cases without hiding vanilla differences.
- Keep each landed sub-slice covered by focused unit tests and update readiness
  claims only for behavior that actually landed.

## Non-Goals

- Exact vanilla RNG, growth-rate, light, moisture, biome, or support parity.
- Complex feature generation, worldgen decoration parity, vines, full mushroom
  spreading, full chorus growth, or full kelp underwater parity.
- New protocol work, particles, sounds, statistics, game events, level events,
  or block entity metadata.
- Timing-dependent wire harness coverage for random-tick behavior.

## Strategy

1. Land stem fruit placement as the first sub-slice because M62 explicitly left
   it open and it fits the existing random-tick/bonemeal block-edit model.
2. Then take the next smallest visible lifecycle gaps from the readiness list,
   stopping at a green, coherent bucket rather than spinning up a new milestone
   per plant.
3. Keep exclusions explicit in `docs/REPLACEMENT_READINESS.md` so local Solaris
   behavior is not mistaken for vanilla parity.

## Follow-On Milestones

- M67 is a codebase-wide review milestone: first enumerate core behavior
  divergences from vanilla, then review the codebase for duplicate/dead code,
  one-use helpers, and unnecessary module coupling.
- M68 starts the cleanup track from the M67 findings. M67 should write the M68
  backlog instead of mixing review and cleanup in the same milestone.

## Closeout Notes

M66 deliberately grouped several simple plant lifecycle slices into one
milestone. Kelp, chorus, mushroom spread, exact plant support checks, exact loot
RNG, particles/sounds/statistics/game events, and harness coverage remain
outside the claim and should be reviewed during M67 before more cleanup or
parity work is scheduled.
