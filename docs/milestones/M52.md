# M52 - Multicore regression gates and extension boundaries

**Status:** in progress. Branch:
`dev/M52-multicore-gates-extension-boundaries`, cut from `main` at `m51`.
**Owning crates:** `mc-test-harness` for load/backpressure gates, `mc-net` for
runtime metrics and custom payload integration, `mc-extension` and `mc-script` for
future plugin boundaries, and `docs` for operator-facing performance notes.

## Goal

Make multicore performance regressions visible in CI-style tests and define safe
extension/script boundaries before plugins can block or mutate server-core state.

M52 is the guardrail milestone after M48-M51. It should turn the review findings
into durable tests, metrics, and API constraints so future gameplay work cannot
accidentally reintroduce runtime blocking, unbounded queues, or world/session lock
exposure.

## Scope

- Non-ignored multicore and slow-reader regression tests.
- Lock pressure, queue depth, worker permit, and cache metrics assertions.
- Test helper improvements so negative assertions require liveness.
- Minimal `mc-extension` event/command boundary with bounded queues.
- Minimal `mc-script` execution model contract, without implementing a full VM.

## Non-Goals

- Full plugin runtime, Lua, WASM, or sandbox implementation.
- Gameplay parity changes.
- Replacing all existing harness tests.
- Release-build benchmarking; dev/debug gates remain the baseline.

## Current Gaps

- Harness async tests use default current-thread Tokio; none exercise a
  multi-thread runtime shape.
- The named load scenario is ignored, mostly sequential, and prints metrics without
  assertions.
- Tests eagerly drain clients and do not cover slow-reader backpressure.
- Some negative assertions can pass while the server is stalled because no liveness
  signal is required.
- `mc-extension` and `mc-script` are workspace stubs, so future hooks have no
  bounded dispatch or lock-exposure rules.

## Strategy

1. Convert the smallest useful subset of load diagnostics into non-ignored tests.
2. Assert loose but real ceilings so tests catch regressions without becoming
   flaky microbenchmarks.
3. Add reusable harness probes for slow readers, skipped-frame volume, and positive
   liveness during negative windows.
4. Define extension/script APIs as event snapshots in, bounded commands out.
5. Explicitly forbid exposing `WorldHandle`, `SessionRegistry`, or locked storage
   to extension/script code.

## Sub-Milestones

### M52.a - Multicore Harness Baseline

Acceptance:

- Add one or more non-ignored tests using `#[tokio::test(flavor = "multi_thread",
  worker_threads = 4)]`.
- Tests cover concurrent login/chunk streaming and at least one gameplay broadcast
  path.
- Assertions cover elapsed time, lock pressure, or worker budget ceilings with
  documented tolerance.
- Existing correctness tests remain unchanged unless they need shared helpers.

### M52.b - Slow Reader and Backpressure Probes

Acceptance:

- Add a reusable paused/slow reader client helper.
- A regression test proves one slow observer does not starve an active client.
- Outbound queue saturation behavior is observable through metrics or test hooks.
- Reliable/coalesced lanes from M50 are covered if they exist by this milestone.

### M52.c - Harness Liveness and Frame-Volume Guards

Acceptance:

- Negative assertion helpers require a positive liveness signal before passing.
- Targeted frame waits can report or cap skipped frame count/bytes in selected
  latency-sensitive tests.
- The ignored manual load report is updated to use the shared helpers or clearly
  remains diagnostic-only.

### M52.d - Extension Boundary Skeleton

Acceptance:

- `mc-extension` defines typed inbound events and outbound commands with bounded
  queue semantics.
- Custom payload handling in `mc-net` has a documented path to forward allowed
  payloads through the boundary.
- Unknown or oversized custom payloads are bounded and cannot force large ignored
  copies.
- Tests cover queue-full behavior and payload size rejection.

### M52.e - Script Runtime Contract

Acceptance:

- `mc-script` documents and exposes a minimal host/runtime contract: immutable
  event DTOs in, bounded command batches out.
- The API does not expose `WorldHandle`, `SessionRegistry`, `WorldStorage`, or
  other lock-owning server internals.
- The contract reserves CPU/fuel, memory, timeout, and shutdown controls for the
  future VM implementation.
- Placeholder tests are replaced with API-level boundary tests.

### M52.f - Operator Performance Notes and Closeout

Acceptance:

- Document the debug-build load gates and how to read lock/queue metrics.
- Record expected limits and known non-goals for extension/script performance.
- Baseline validation passes.

## Validation

```sh
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Focused gates:

```sh
cargo test -p mc-test-harness --test load_scenarios -- --nocapture
cargo test -p mc-test-harness --test player_presence -- --nocapture
cargo test -p mc-test-harness --test chunk_stream -- --nocapture
cargo test -p mc-extension --lib -- --nocapture
cargo test -p mc-script --lib -- --nocapture
```

## Risks

- Performance assertions can be flaky if they are too tight; start with coarse
  invariants and lock/permit counts, not microsecond budgets.
- Extension/script APIs can ossify too early; keep the skeleton small and focused
  on safety boundaries.
- Slow-reader tests must avoid hanging CI; every probe needs bounded timeouts.
