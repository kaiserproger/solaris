# M80 - Loot, Recipes, And Data-Driven Survival Core

**Status:** Planned. Quality label: `draft`.

## Agent Start Prompt

Read M77-M79, M57-M64, M72-M73, `mc-data`, and the validation ledger. Run
preflight. Implement only ledger-ranked M100 blockers.

## Goal

Move common survival drops and recipes from simple deterministic support
toward scoped data-backed behavior without claiming full datapack parity.

## Scope

- Loot pools, rolls, `set_count`, simple random count ranges,
  `survives_explosion`, common tool predicates, fortune/silk-touch basics
  for scoped blocks, and looting basics if feasible.
- Verify shaped/shapeless/smelting/blasting/smoking/campfire recipes
  against sidecar and fallback data.
- Make unsupported loot/datapack features visible in logs and readiness.
- Cover dropped-item metadata, merge, pickup contention, overflow,
  despawn, save/restart, and two-client visibility for scoped drops.
- Decide how deterministic crop/plant special cases interact with the
  sidecar executor.

## Acceptance

- Common survival block and mob drops have runtime tests and oracle/data
  citations.
- Deterministic fallback remains explicit and does not count as vanilla
  parity.
- Validation ledger rows touched by loot/recipes are updated.

## Implementer 3 Slice - Counted Simple Loot

Quality label: `draft`.

This slice extends the M73 simple vanilla loot subset without broad datapack
claims:

- `mc-data` now represents loaded block/entity loot as one item stack with a
  bounded count, preserving the old identifier-only accessors for existing code.
- The vanilla subset loader accepts constant `minecraft:set_count` functions at
  pool or entry level when the count is `1..=64`.
- Unsupported functions, including looting/tool/enchantment functions and
  non-constant `set_count` shapes, are skipped instead of treated as parity.
- `mc-net` block and mob drop helpers now emit the configured count for loaded
  loot stacks; deterministic plant/crop special cases still bypass this path.

Focused coverage:

- `cargo test -p mc-data loot::tests -- --nocapture`
- `cargo test -p mc-net block_drop_configured_loot_count_reaches_runtime_stack -- --nocapture`

Known gaps left for later M80/M95 work: random count ranges, multiple pools or
multiple item stacks, fortune/silk touch, tool predicates, looting, equipment
drops, explosion decay, recipe execution/book sync, and vanilla oracle/client
evidence.
