# M80 - Loot, Recipes, And Data-Driven Survival Core

**Status:** Planned. Quality label: `draft`.

## Agent Start Prompt

Read M77-M79, M57-M64, M72-M73, `mc-data`, and the validation ledger. Run
preflight. Implement only ledger-ranked M100 blockers.

## Goal

Move common survival drops and recipes from simple deterministic support
toward scoped data-backed behavior without claiming full datapack parity.

## Scope

- Loot pools, rolls, `set_count`, simple random count ranges,
  `survives_explosion`, common tool predicates, fortune/silk-touch basics
  for scoped blocks, and looting basics if feasible.
- Verify shaped/shapeless/smelting/blasting/smoking/campfire recipes
  against sidecar and fallback data.
- Make unsupported loot/datapack features visible in logs and readiness.
- Cover dropped-item metadata, merge, pickup contention, overflow,
  despawn, save/restart, and two-client visibility for scoped drops.
- Decide how deterministic crop/plant special cases interact with the
  sidecar executor.

## Acceptance

- Common survival block and mob drops have runtime tests and oracle/data
  citations.
- Deterministic fallback remains explicit and does not count as vanilla
  parity.
- Validation ledger rows touched by loot/recipes are updated.
