# M46 - Collision and fall parity

**Status:** draft plan for owner review. Proposed branch:
`dev/M46-collision-fall-parity`, cut from `main` after the preceding milestone tag.
**Owning crates:** `mc-physics` for movement primitives, `mc-net` for player/entity
fall damage and play-state correction behavior, `mc-test-harness` for vanilla and
Solaris observations.

## Goal

Capture and fix the M44-deferred collision and fall-damage gaps without turning
Solaris into a broad movement rewrite.

## Scope

- Flat-ground settling and no-correction behavior.
- Wall collision and correction behavior.
- One selected step-up/non-step-up case.
- Landing fall damage threshold and amount.
- Water-entry fall-damage suppression.

## Non-Goals

- Full vanilla movement engine parity.
- Entity-vs-entity push/collision.
- Boats, vehicles, projectiles, or elytra.
- Broad pathfinding polish.

## Strategy

1. Capture `collision-wall-step-fall` against vanilla first.
2. Build matching Solaris observations through real play paths.
3. Change physics or damage rules only where the vanilla/Solaris mismatch is
   explicit.
4. Keep each fix isolated so failed manual behavior can be bisected.

## Sub-Milestones

### M46.a - Vanilla Collision/Fall Oracle

Acceptance:

- `wire-probe` or harness tooling records the selected flat-ground, wall,
  step-up, landing, and water-entry windows.
- Captures stay local under `.analysis/physics-oracles/`.
- The doc records packet/damage signals and tolerances.

### M46.b - Solaris Comparison Tests

Acceptance:

- Real play-path tests compare corrections, positions, damage, or health updates
  for the captured cases.
- Tests skip clearly when local vanilla sidecars are missing.
- Manufactured physics-only assertions are not used as parity evidence.

### M46.c - Minimal Collision Fixes

Acceptance:

- Fixes are limited to captured wall/step/ground mismatches.
- Existing reach, block edit, mob, and player presence tests remain green.
- Any remaining collision mismatch is listed with its missing oracle.

### M46.d - Minimal Fall-Damage Fixes

Acceptance:

- Landing and water-entry behavior match the selected oracle cases.
- Survival damage and death/respawn tests remain green.
- Fall-damage changes do not affect debug damage command semantics.

### M46.e - Closeout

Acceptance:

- Map every fix to a capture line or harness oracle.
- Route entity-vs-entity push/collision separately if still needed.

```sh
cargo test -p mc-test-harness --test block_edit -- --nocapture
cargo test -p mc-test-harness --test player_presence -- --nocapture
```

## Risks

- Small movement constant changes can cascade into reach, mining, and mob melee.
- Vanilla correction behavior may be visual/client-predicted rather than purely
  server-authoritative.
- Fall-damage fixes can conflict with water, ladders, and future block types if
  scoped too broadly.
