# M49 - World storage snapshots and cache bounds

**Status:** in progress on `dev/M49-world-storage-snapshots`, cut from `main`
after the M48 tag.
**Owning crates:** `mc-world` for storage/cache shape, `mc-net` for chunk
streaming, relight, block edit, random/fluid tick callers, `mc-worldgen` for
generated chunk insertion, and `mc-test-harness` for lock/memory regression
coverage.

## Goal

Break the single global world-lock bottleneck for read-heavy paths and bound the
largest chunk/light caches without changing gameplay semantics.

M49 should make chunk, light, and physics readers consume immutable snapshots
where possible. Mutating block edits and chunk commits may remain serialized, but
read-only cached access should no longer require cloning full chunks under the
global `WorldStorage` mutex.

## Scope

- Immutable cached chunk snapshots for chunk streaming, light, and physics reads.
- Shorter world-lock hold times for relight, random ticks, fluid ticks, and block
  edits.
- Prepared chunk cache count/byte bounds.
- Dirty chunk and region cache pressure controls.
- Region decode memory review after M48 offload.

## Non-Goals

- Full actor-based world simulation.
- Broad fluid/falling-block parity changes; M47 owns behavior.
- Session/entity visibility rewrite; M50 owns that.
- Wire compression rewrite; M51 owns that.

## Current Bottlenecks

- `WorldHandle` is one `Arc<tokio::sync::Mutex<WorldStorage>>` because reads touch
  LRU state.
- Cached chunk snapshots clone whole `Chunk` values while the world lock is held.
- Relight and chunk streaming may clone 3x3 chunk neighborhoods.
- Prepared chunk cache retains full framed payloads and optional light data until
  ticket release/invalidation, with no byte cap.
- Generated/dirty chunks can stay resident beyond nominal clean cache pressure
  until a flush occurs.

## Strategy

1. Add snapshot-oriented read APIs before changing storage internals broadly.
2. Store cached chunks as shared immutable handles where safe, with copy-on-write
   or revision invalidation for mutations.
3. Move LRU touch/accounting out of read-critical lock hold where possible.
4. Add explicit byte/count bounds to prepared and dirty/cache-heavy paths.
5. Use lock-pressure metrics as acceptance criteria, not just diagnostics.

## Sub-Milestones

### M49.a - Cached Chunk Snapshot API

Acceptance:

- `mc-world` exposes a read-only cached chunk snapshot API that returns cheap shared
  handles instead of cloning full `Chunk` values.
- Chunk streaming and relight use the snapshot API for cached center/neighbour
  chunks.
- Mutations invalidate or replace snapshots safely.
- Existing chunk, block edit, relight, and persistence tests remain green.

### M49.b - World Read Lock Reduction

Acceptance:

- Physics sampling, random ticks, fluid ticks, and container/block read paths avoid
  generating or disk-loading chunks while holding the hot world lock.
- Any read path that still can call generation or region decode is documented with
  a follow-up.
- `WorldStorage` lock metrics show shorter max hold under the M48 multicore load
  gate.

### M49.c - Prepared Chunk Cache Bounds

Acceptance:

- `SessionRegistry` prepared chunk cache has count and/or byte bounds.
- Eviction is LRU- or priority-based and safe under active tickets.
- Metrics expose cache entries, estimated bytes, hits, misses, and evictions.
- Clients still receive required chunk/light data after eviction.

### M49.d - Dirty and Region Cache Pressure

Acceptance:

- Dirty generated chunks cannot grow memory unbounded without a visible background
  flush or pressure signal.
- Region cache memory behavior is documented after M48 moves disk/decode off the
  runtime.
- If full-region decompressed caching remains, it has capacity-aware accounting.
- Save/flush correctness remains unchanged.

### M49.e - Light Payload Sharing

Acceptance:

- Repeated full-sky and unchanged light layers avoid per-send `Vec` allocation
  where practical.
- Chunk/light wire structs can reference shared immutable payloads or reuse buffers
  without changing packet layout.
- Existing incremental relight and chunk stream tests remain green.

### M49.f - Closeout

Acceptance:

- Document remaining world serialization points and whether they are intentional
  mutation boundaries.
- Record memory/lock metrics from the focused multicore gate.
- Baseline validation passes.

## Risks

- Snapshot handles can hide stale world state if invalidation is incomplete.
- Cache bounds can trade memory safety for extra rebuild CPU; measure both.
- Dirty-cache pressure must never drop unsaved chunk edits.
