- Import unresolved M39.c-M39.h and M49.b-M49.e items as checklist rows.

## 2026-07-11 Prompt 03 Single-Writer Pickup Slice

Quality label: `stabilization`.

ADR 0004 stages ADR 0003 instead of replacing the runtime in one pass. A new
explicit `SimulationHandle`/non-clone `SimulationOwner` pair uses a bounded
1024-entry queue. Accepted commands receive monotonic sequence numbers; the
owner drains and orders at most 256 commands before entity goals/physics on
each tick. Runtime telemetry exposes capacity, current/max depth, enqueue,
dequeue, processed, full/closed/shutdown rejection, cancellation, and max-batch
counters.

The first authority transfer covers item, XP, and grounded-arrow entity claims. Network tasks
may still discover immutable nearby snapshots and calculate available player
inventory space, but authoritative claim/removal requires the private
`SimulationAuthority` held only by the ticker owner. Production `play.rs` has
no direct item/XP/arrow entity claim mutation. Queue-full/closed requests fail before
local reward or entity mutation; shutdown closes and rejects unapplied work.
Legacy direct claim helpers compile only under `cfg(test)` for dual-path replay.

The initial seven focused simulation tests cover capacity, full rejection, sequence order,
budget carry-over, cancellation, shutdown, and normalized legacy-vs-owner
item/XP outcomes. `mc-net` passed 450/450 tests. The real TCP
`survival_break_drops_item_entity_and_picks_it_up` path observed the same
slot/take/remove packets and exactly one processed item-pickup command. After
passive herd commands joined the same queue, the focused run reported capacity
1024, enqueued/processed 26, item pickups 1, depth 0, max depth/batch 24, and no
rejection or cancellation. Prompt 02 deterministic replay
passed twice-backed persistence again in 8.81 seconds; its short 4+1 soak passed
in 26.50 seconds with four transaction samples, 111 healthy-client entity
spawns, max one reliable retry in flight, and a clean final save.

The post-slice workspace checkpoint passed `cargo test --workspace`, full
workspace clippy with `-D warnings`, format, code-health (`0 fail`, `KEEP`),
and `git diff --check`. Default workspace execution kept local sidecar, oracle,
load, and performance scenarios explicitly ignored rather than counting them as
fresh evidence.

The follow-on entity-lifecycle extension routes `/summon`, bow projectile
creation, and player melee through the same owner. One melee command now commits
damage, optional knockback, lethal removal, and planned item/XP rewards under a
single registry lock. Bow ammunition and durability are consumed only after a
successful owner response, so full/closed queue rejection does not create an
unbacked inventory debit. Production direct helpers for command spawn, arrow
spawn, melee damage, melee knockback, lethal removal, and all three pickup kinds
are authority-gated; legacy comparison helpers are `cfg(test)` only.

Sixteen simulation tests now include normalized arrow claim, nonlethal/lethal
combat, duplicate lethal rejection, full-queue no-damage, command spawn, and
arrow/passive-herd spawn comparisons plus detached-event and owner-tick checks.
Production lifecycle clock, goals/query, physics apply, arrow-hit resolution,
and startup entity restore are authority-gated through `SimulationOwner`.
`mc-net` passed 459/459; all six parallel mob-presence tests and the bow
spawn/motion/despawn test passed. A blocking per-chunk herd response initially
inflated the parallel mob gate to a 44-second timeout; detached ordered herd
commands restored it to 11.91 seconds while preserving bounded queue pressure.

After the complete entity slice, checked Prompt 02 replay again produced 12
entities/25 chunks in both runs (`8.79 s`). The short 4+1 soak passed in `27.52
s` with four transaction samples, 111 active-client entity spawns, max one
reliable retry in flight, one saved entity, and 28 flushed chunks. Full workspace
tests, workspace clippy with `-D warnings`, format, code-health, and diff checks
passed; default ignored oracle/load/performance rows remain non-evidence.

This is not whole-runtime single-writer evidence. Generic item/XP and
player-drop spawn, falling-block/world landing coupling, player inventory/XP
ownership, blocks, containers, scheduled ticks, world storage, and persistence
writes remain legacy. A requester
cancellation racing after owner apply but before oneshot delivery also remains
open until player inventory/XP moves into the same owner transaction. P4/P42,
broad lock comparison, the 30-minute replay, long soak, performance, vanilla
oracle, and fresh real-client gates were not rerun for this extension.

### Shared chest and furnace click extension

Network chest/furnace clicks now send expected and updated block-entity
snapshots through the bounded owner. The owner compares world state, performs
the viewer state-id claim and world write as one `world -> session` critical
section, and returns either peer dispatches or an authoritative rejection
snapshot. Connection-local inventory/cursor changes are rolled back on stale,
busy, unavailable, queue, or storage failure. A follow-up regression fixed the
read-side equivalent: initial world content and viewer state id are now read
under the same lock order, so resync cannot pair a new id with stale slots.

Four owner tests cover chest/furnace direct-vs-owner equivalence, one winner
for duplicate chest snapshots, and busy-world no-mutation. The paired-snapshot
race regression and all 467 `mc-net` tests passed. All 66 `block_edit` TCP tests
passed. The explicit two-client chest contention gate processed exactly two
container commands, committed one cursor transaction, conserved both items,
and reported zero busy/unavailable/mutation failures. Stale chest/furnace and
normal furnace-smelt TCP paths passed.

Checked replay passed with normalized state equality; the two saves reported
8/4 entities and 24/25 chunks because incidental background entities/chunk
flush counts are outside the normalized transaction state. The short 4+1 soak
passed in `21.50 s` with five transaction samples, 135 active-client entity
spawns, 274 visibility drops, four retries, max one retry in flight, one saved
entity, and 28 flushed chunks.

This is network click authority only. Furnace ticking, hopper/server-origin
container writes, player inventory/cursor ownership, cancellation after owner
apply, other block entities, and persistence remain staged.

The post-slice checkpoint passed full workspace tests, workspace clippy with
