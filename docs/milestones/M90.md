### Implementer 13/20 - Dirty flush commit correctness guard

Preflight: full on `/tmp/opencode/solaris-worktrees/M90` branch
`dev/M90-concurrency-ownership`; Rust 1.94.1, Cargo 1.94.1, rustfmt,

were present.

Slice: hardened the `save_all_flush` dirty flush commit correctness guard.
`DirtyFlushPlan` records a per-chunk dirty-generation token with each planned
payload, but `commit_dirty_flush` still re-encodes matching-generation dirty
chunks under the `SaveAllFlush` lock before clearing them. That keeps chunks
changed after planning dirty even when a post-plan mutation did not bump the
token.

Ownership result: dirty region writes still run outside the world lock; commit
does not implement the intended dirty-commit fast path and does not honestly
narrow the `SaveAllFlush` lock hold for unchanged dirty chunks. Treat this M90
slice as a correctness guard with degraded performance until M91 or a measured
follow-up proves a safe fast path. It does not claim the generated-world
`chunk_prepare` blocker is green; chunk prepare disk/generation commit, light
compute, dirty flush commit cost, and live probe budget evidence remain M90/M91
debt.
