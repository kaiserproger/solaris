# M51 - Autonomous parity, Tellus terrain, AI, and runtime smoothness

**Status:** draft plan for owner review. Branch:
`dev/M51-core-parity-tellus-ai-perf`, cut from `main` at `m50`.
**Owning crates:** `mc-test-harness` for autonomous e2e parity probing,
`mc-net` for gameplay/session/runtime fixes, `mc-world` and `mc-worldgen` for
world-state and Tellus-style terrain, `mc-entity` for AI facts/goals, and `docs`
for oracle/decompilation notes.

## Goal

Build an autonomous end-to-end core tester that compares Solaris against a local
vanilla 26.1.x oracle, use it to find and fix one-to-one world-state gameplay
flaws, then extend world generation toward Tellus-style Earth/climate terrain,
improve lock/backpressure behavior, and make mob AI closer to vanilla while
preserving batch/multi-thread execution.

M51 is intentionally broad, but each sub-milestone must stay test-first: every
bug fix starts with a harness or unit regression that fails on current Solaris and
passes after the root-cause fix. Nether and End dimensions remain out of scope.

## Scope

- Autonomous e2e core tester continuation of `mc-test-harness`.
- Vanilla oracle runner and scenario DSL for deterministic, bounded parity checks.
- First batch of discovered one-to-one overworld world-state fixes.
- Tellus source/decompiled-source study and a repo-owned terrain design derived
  from observable behavior and public/source-available code, not copied assets.
- Tellus-inspired Overworld terrain/climate prototype behind config/test gates.
- Deadlock/race/starvation diagnostics for session/world/chunk/entity hot paths.
- Mob AI upgrades that keep fact collection, goal selection, and motion batches
  separated from long-held locks.

## Non-Goals

- Nether or End dimensions.
- Bit-perfect vanilla parity for every system.
- Copying Tellus code verbatim or vendoring Tellus data/assets.
- Online geographic data dependency in Solaris runtime during this milestone.
- Full production plugin/script runtime.
- Release-build benchmarking; dev/debug gates remain the owner workflow.

## Current Evidence

- M50 left known risks around entity goal ticking under the session registry lock,
  permanently slow clients holding bounded queue capacity, and per-entity physics
  sample allocation.
- `mc-extension` and `mc-script` are stubs; they are not the focus unless needed
  for test isolation.
- Existing harness tests validate many direct flows but do not autonomously explore
  action sequences or compare final world state against vanilla.
- Tellus public README describes Earth-scale terrain from geographic elevation,
  land cover, climate/weather data, Distant Horizons LOD integration, and map
  teleport/config commands. Source is available at `Yucareux/Tellus`; use source
  study/decompilation only for design understanding and cite paths in notes.

## Strategy

1. Treat vanilla as the oracle. For each scenario, run the same scripted client
   actions against vanilla and Solaris, then compare normalized observations.
2. Compare stable world/player facts, not raw implementation internals: block
   states, inventories, entities, health/food/xp, drops, container contents,
   selected packets, and persistence after restart.
3. Start with small deterministic scenarios that current harness already knows how
   to drive, then add bounded exploration and shrinking once the oracle pipeline is
   reliable.
4. For every parity mismatch: record repro, root cause, regression test, minimal
   fix, focused validation.
5. For Tellus: build a local design dossier first, then implement Solaris-native
   terrain primitives incrementally behind config flags.
6. For smoothness: instrument before optimizing. Add tests that prove liveness and
   bounded lock/queue/worker pressure before changing scheduling.
7. For AI: collect read-only facts in batches, decide goals without holding world
   or session locks, then apply compact movement/action commands on the game path.

## Sub-Milestones

### M51.a - Vanilla Oracle Scenario Runner

Acceptance:

- `mc-test-harness` can launch or attach to a local vanilla 26.1.x server jar from
  `.analysis/server.jar` without committing Mojang bytes.
- A shared scenario trait/DSL can run the same scripted flow against Solaris and
  vanilla.
- At least one smoke scenario reaches Play, observes spawn facts, performs one
  block edit, and shuts down both servers cleanly.
- Tests are skipped with a clear message when `.analysis/server.jar` is absent;
  they are not false-green when the oracle is configured.

### M51.b - Normalized World-State Diff Engine

Acceptance:

- Add normalized observation structs for block samples, inventory, health/food/xp,
  selected entities/drops, container contents, and persistence markers.
- Diff output points at exact scenario step and fact path.
- First parity scenario compares Solaris and vanilla for a tiny break/place flow.
- Mismatches can be serialized to `.analysis/parity/` for local debugging, but no
  oracle output is tracked in git.

### M51.c - Autonomous Core Fuzzer, Bounded and Shrinkable

Acceptance:

- Add a deterministic action generator for bounded overworld survival actions:
  move, look, break, place, use item, open/click/close container, attack, wait,
  reconnect, restart.
- Generator has seed, step count, timeout, and scenario whitelist controls.
- On mismatch, the runner records seed and minimized prefix where practical.
- A non-ignored short Solaris-only invariant test runs in CI; vanilla-backed deep
  parity can remain ignored/manual if it requires the local jar.

### M51.d - First Parity Bug Batch

Acceptance:

- Use M51.a-c to find at least three real Solaris-vs-vanilla mismatches in current
  scoped overworld gameplay.
- For each mismatch, write/keep a failing regression before fixing.
- Fixes preserve existing harness behavior and do not broaden claimed readiness
  beyond documented scope.
- Document remaining parity gaps found but not fixed.

### M51.e - Tellus Source Study and Terrain Design

Acceptance:

- Fetch or decompile Tellus locally under `.analysis/tellus/` only.
- Document architecture notes: coordinate mapping, elevation sampling, biome/climate
  placement, water/coast handling, structure/road/building strategy if present,
  caching, async IO, and Distant Horizons/LOD approach.
- Translate findings into Solaris-native design; do not copy Tellus code/assets.
- Add config shape for selecting `vanilla_like` vs `tellus_like` worldgen without
  changing the default owner/manual gate unexpectedly.

### M51.f - Tellus-Inspired Overworld Prototype

Acceptance:

- Implement a deterministic offline Tellus-like terrain mode using repo-owned math
  and optional local sidecar fixtures, not live internet dependencies.
- Terrain has broad continental/coastal elevation, climate/biome bands, water level,
  smoother mountain/valley shapes, and visual variety closer to Tellus than the
  current generator.
- Existing worldgen tests remain deterministic across seeds.
- Add focused tests for coordinate scale, height bounds, biome/climate selection,
  and chunk seam continuity.

### M51.g - Runtime Lock/Starvation Audit and Gates

Acceptance:

- Add diagnostics for session registry, world storage, chunk pipeline, entity AI,
  outbound queues, and worker permit pressure.
- Add at least two non-ignored liveness tests that require positive progress under
  load or slow-reader conditions.
- Identify and fix any deadlock/race/starvation issue reproduced by the tests.
- Record remaining hot locks with file/function references and pressure metrics.

### M51.h - Vanilla-Closer Batched Mob AI

Acceptance:

- Split AI into fact collection, per-entity goal decision, and application phases.
- Preserve batch/multi-thread execution for expensive decision work; no worker can
  mutate world/session state directly.
- Add vanilla-like basics for common mobs already in scope: acquire/forget target,
  wander, avoid hazards where cheaply observable, melee cadence/reach, passive
  panic/flee, item/drop pickup only where already supported.
- Add harness tests for observable AI behavior with multiple clients and loaded vs
  unloaded chunks.

### M51.i - Closeout and Readiness Update

Acceptance:

- Update `docs/REPLACEMENT_READINESS.md` with exact parity claims, partial claims,
  and known gaps discovered by the autonomous tester.
- Update README status if still stale.
- Baseline validation passes.
- `What Landed Where` is completed with commits/artifacts.

## Validation

Baseline:

```sh
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Focused gates:

```sh
cargo test -p mc-test-harness --test parity_oracle -- --nocapture
cargo test -p mc-test-harness --test load_scenarios -- --nocapture
cargo test -p mc-test-harness --test mob_presence -- --nocapture
cargo test -p mc-worldgen --lib -- --nocapture
cargo test -p mc-net --lib -- --nocapture
```

Manual/local oracle gates when `.analysis/server.jar` is present:

```sh
cargo test -p mc-test-harness --test parity_oracle -- --ignored --nocapture
cargo run --bin mc-server -- --check --config example.toml
```

## Risks

- Vanilla oracle tests can become slow or flaky; keep non-ignored gates short and
  make deep parity opt-in/manual until stable.
- World-state diffing can overfit to packet order; compare normalized facts and
  cite exact reasons when packet order is itself the bug.
- Tellus may depend on online services and client/rendering assumptions that do not
  fit Solaris server runtime; keep Solaris runtime offline-deterministic by
  default.
- AI improvements can easily reintroduce long locks; batch facts and commands,
  never worker-side mutations.
- Performance gates in debug builds must assert coarse invariants, not tight
  benchmark numbers.
