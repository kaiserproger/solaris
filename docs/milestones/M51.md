# M51 - Protocol, NBT, and immutable data hardening

**Status:** draft plan for owner review. Proposed branch:
`dev/M51-protocol-nbt-data-hardening`, cut from `main` after the preceding
milestone tag.
**Owning crates:** `mc-protocol` for frame and packet allocation/limits, `mc-nbt`
for parser and writer limits, `mc-world` for region decompression integration,
`mc-data` for immutable registry/data sharing, and `mc-net` for packet write paths.

## Goal

Reduce large-packet copying and harden NBT/protocol/data paths against avoidable
memory spikes without changing wire layouts.

M51 is not a gameplay milestone. It is a memory, robustness, and throughput pass
over the data formats that feed chunk streaming, login/configuration, and world
load/save.

## Scope

- Frame encode/decode buffer reuse and fewer large copies.
- Offloaded or thresholded compression for non-chunk large packets.
- Bounded packet counts and custom payload sizes.
- NBT recursion, length, and decompressed-size limits.
- Immutable registry/recipe/biome sharing instead of per-connection clones.
- Data lookup table shape for hot light/material paths where it belongs in
  `mc-data`.

## Non-Goals

- New protocol packet IDs or layouts without ADR 0002 oracle support.
- Chunk pipeline scheduling; M48 owns that.
- World snapshot/cache redesign; M49 owns that.
- Session/entity scaling; M50 owns that.

## Current Bottlenecks

- `encode_frame` builds `[id][body]`, compressed `Vec`, and final frame, causing
  multiple full-packet copies.
- General `write_packet` can zlib-compress large non-chunk packets inline on async
  connection tasks.
- Several packet decoders allocate `Vec::with_capacity(count)` from untrusted
  VarInt counts before tight caps.
- NBT recursive parse/write has no depth limit, and array/list lengths are not
  bounded by actual byte budget.
- Region/player/template decompression uses `read_to_end` without decompressed-size
  caps.
- Per-play-session biome registry and recipe clones duplicate immutable data.

## Strategy

1. Keep packet layout byte-for-byte compatible; optimize buffers around it.
2. Add small bounded helpers for counts, payload lengths, and NBT limits before
   changing call sites broadly.
3. Prefer shared immutable `Arc`/`Bytes` data for static registries and bulk packet
   payloads.
4. Keep robustness limits conservative and documented; fail closed on corrupt data.
5. Add tests for malicious/small-input large-allocation cases.

## Sub-Milestones

### M51.a - Frame Buffer and Compression Path

Acceptance:

- Add an `encode_frame_into` or equivalent API that can reuse caller buffers.
- Compressed frames stream varint id and body into zlib without an intermediate
  full `plain` copy.
- Large non-chunk packet compression is offloaded or thresholded so it does not
  monopolize async connection tasks.
- Existing protocol frame tests remain byte-compatible.

### M51.b - Packet Count and Payload Bounds

Acceptance:

- Packet decoders use bounded count helpers for arrays/lists driven by client or
  external input.
- Unknown custom payloads have a protocol/state-specific max below the global frame
  cap or are represented without copying ignored bytes.
- Tests cover tiny frames that advertise huge counts.
- Legitimate harness packets still decode.

### M51.c - NBT Depth, Length, and Decompression Limits

Acceptance:

- `mc-nbt` rejects nested compounds/lists above a documented depth limit.
- NBT list/array allocation is bounded by both element count and remaining/minimum
  byte budget where possible.
- Region, playerdata, and structure decompression cap decompressed bytes before
  parsing.
- Corrupt or oversized NBT returns errors instead of panicking or allocating huge
  buffers.

### M51.d - NBT ByteArray and Chunk Extras Copy Reduction

Acceptance:

- ByteArray read/write avoids unnecessary per-byte work where safe under the
  current public API.
- Chunk load/save preserves unknown extras without repeatedly cloning large `Tag`
  trees where practical.
- Existing chunk round-trip and persistence tests remain green.

### M51.e - Immutable Data Sharing

Acceptance:

- Play sessions no longer clone full recipe lists or biome registry entries.
- `VanillaData` or `ServerConfig` exposes shared immutable handles for registries
  used at runtime.
- Startup registry JSON consumers avoid repeated full parses where practical.
- Runtime light/material lookup tables use cache-friendly dense facts where this
  belongs in `mc-data`.

### M51.f - Closeout

Acceptance:

- Document all new size/depth limits and why they are safe for current fixtures.
- Record any remaining double-copy packet paths with file references.
- Baseline validation passes.

## Risks

- Protocol buffer rewrites can create subtle byte layout regressions; keep
  golden/frame tests tight.
- NBT limits that are too small can reject real worlds; document values and test
  against local `.analysis/test-world` when available.
- Shared immutable data changes can ripple through ownership APIs; avoid broad
  backwards-compatibility shims unless external consumers exist.
