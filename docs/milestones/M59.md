# M59 - Common crop harvest drops

**Status:** Closed out after M59.c. M59.a carrot drops committed; M59.b
potato drops committed; M59.c beetroot and nether wart drops committed; M59.d
docs closeout completed. Branch:
`dev/M59-common-crop-harvest-drops`, cut from `main` after M58 closeout.
**Owning crates:** `mc-net` for deterministic crop-drop rules and survival block
break integration, `mc-test-harness` for Solaris-only survival coverage, `docs`
for readiness updates at closeout.

## Goal

Finish the visible farming harvest loop for the common age-based crops Solaris
can already grow: carrots, potatoes, beetroots, and nether wart should drop
useful deterministic harvest items when broken by a survival player.

M57 made these crops grow through random ticks and bonemeal. M58 proved the
crop-aware multi-drop seam with wheat. M59 extends that seam to the remaining
supported crops without new packets, guessed metadata, vanilla loot-table
execution, or protocol oracle work.

## Scope

- Extend the existing M58 crop-drop helper beyond wheat to carrots, potatoes,
  beetroots, and nether wart.
- Start with a small M59.a vertical slice for carrots only.
- Keep harvest rules deterministic and deliberately modest:
  - mature carrots drop `minecraft:carrot` x2;
  - immature carrots drop `minecraft:carrot` x1;
  - mature potatoes drop `minecraft:potato` x2;
  - immature potatoes drop `minecraft:potato` x1;
  - mature beetroots drop `minecraft:beetroot` x1 and
    `minecraft:beetroot_seeds` x1;
  - immature beetroots drop `minecraft:beetroot_seeds` x1;
  - mature nether wart drops `minecraft:nether_wart` x2;
  - immature nether wart drops `minecraft:nether_wart` x1.
- Resolve block maturity from namespaced block id plus the loaded `age` property,
  not numeric block state ids.
- Resolve dropped items by namespaced item registry id and omit only missing item
  ids in minimal test registries.
- Reuse existing block break, block update/ack, item entity spawn, pickup, and
  inventory paths.
- Add focused unit tests first; targeted Solaris harness coverage for non-wheat
  crops remains a follow-up.

## Non-Goals

- Full vanilla loot-table execution.
- Fortune, Silk Touch, tool predicates, explosion decay, luck, RNG extra yields,
  or poisonous potato chance.
- Crop replant automation, villager farming, bees, composters, hoppers,
  farmland hydration changes, or crop trampling changes.
- Sounds, particles, statistics, advancements, recipe-book updates, game events,
  or level-event effects.
- New packet IDs, field layouts, entity metadata, or guessed clientbound effects.
- New growable families such as stems, sweet berry bushes, cocoa, cactus, sugar
  cane, bamboo, kelp, chorus plants, mushrooms, saplings, or trees.

## Strategy

1. Keep M59.a on the verified M58 seam: survival block break receives the
   previous block state, the crop-drop helper returns zero or more registry-backed
   item stacks, and existing item entities make the result visible.
2. Add carrot support first because carrots use the same block id/item id shape
   for planting and harvesting, require no seed secondary drop, and prove the
   non-wheat age/maturity path with minimal surface area.
3. Preserve wheat behavior exactly while extending the explicit supported-crop
   match. Unsupported crop-family blocks must not accidentally gain guessed
   drops.
4. Treat maturity as the crop's known maximum `age` from the loaded block state.
   For M59.a, carrots are mature at `age=7`; ages `0` through `6` are immature.
5. Add focused `mc-net` tests for mature and immature carrots, wheat regression,
   unsupported crop no-override behavior, and missing carrot item id safety.
6. Extend to potatoes, beetroots, and nether wart only after the carrot slice and
   regression tests are green.
7. Defer non-wheat Solaris harness coverage after unit coverage proves the crop
   rules and the M58 mature wheat harness keeps the integration seam covered.
8. Update `docs/REPLACEMENT_READINESS.md` only at closeout with the exact crop
   harvest claims that landed.

## Sub-Milestones

### M59.a - Carrot harvest vertical slice

Target for immediate implementation:

- Extend the existing crop-aware block-drop helper for `minecraft:carrots`.
- When a survival player breaks mature carrots with `age=7`, spawn one item
  stack through the existing item entity path: `minecraft:carrot` x2.
- When a survival player breaks immature carrots with `age=0` through `age=6`,
  spawn `minecraft:carrot` x1.
- Keep wheat behavior from M58 unchanged:
  - mature `minecraft:wheat` with `age=7` drops `minecraft:wheat` x1 plus
    `minecraft:wheat_seeds` x1;
  - immature `minecraft:wheat` with `age=0` through `age=6` drops
    `minecraft:wheat_seeds` x1.
- Resolve `minecraft:carrot` through the item registry by namespaced id; do not
  hardcode numeric item ids or block state ids.
- If `minecraft:carrot` is missing from a minimal test registry, omit the carrot
  stack and do not panic.
- Preserve existing generic block drops for non-crop blocks and preserve
  unsupported-crop behavior for crops not yet claimed by M59.
- Add focused tests proving mature carrots drop two carrots, immature carrots
  drop one carrot, wheat regressions still pass, unsupported crop states do not
  receive guessed carrot-like drops, and missing item ids are safe.

Acceptance:

- Breaking mature carrots visibly produces `minecraft:carrot` x2 using existing
  item entity spawn packets.
- Breaking immature carrots produces `minecraft:carrot` x1 and does not claim
  vanilla RNG or fortune parity.
- Wheat harvest behavior remains unchanged from M58.
- Non-crop generic block drops remain unchanged.
- No new packet IDs, field layouts, entity metadata, sounds, particles,
  statistics, game events, or level events are introduced.
- Focused `mc-net` crop-drop tests pass.

Landed:

- `minecraft:carrots` now use explicit deterministic crop harvest drops:
  mature `age=7` carrots drop `minecraft:carrot` x2 and immature `age=0`
  through `age=6` carrots drop `minecraft:carrot` x1.
- Carrot item stacks resolve through the namespaced item registry id; minimal
  registries without `minecraft:carrot` omit the carrot stack safely.
- Wheat behavior, unsupported-crop behavior, and generic block-drop fallback are
  preserved.
- Focused gate passed: `cargo test -p mc-net carrot -- --nocapture`; format
  check passed.
- Deferred: Solaris harness coverage, potatoes, beetroots, nether wart,
  exact loot/RNG/fortune parity, sounds, particles, statistics, and game events.

## Protocol and Data Oracles

- M59 must not add new packet IDs or field layouts. It should reuse existing
  verified block break, block update/ack, item entity spawn, pickup, inventory,
  and registry paths.
- No `wire-probe` or `javap` oracle is required for M59 if sounds, particles,
  statistics, game events, metadata, level events, and new clientbound effects
  remain deferred.
- Vanilla data sidecar is required for block and item registries. Crop maturity
  must be read from namespaced block id plus the `age` property, not from numeric
  block state ids.
- Crop drop quantities in M59 are Solaris-owned deterministic rules, not a
  translation of Mojang loot-table algorithms.
- If a later slice attempts exact vanilla loot-table execution, fortune/RNG extra
  yields, poisonous potato chance, sounds, particles, statistics, game events,
  level events, or new metadata, first capture or cite the needed behavior from
  the local oracle per ADR 0002 and keep Mojang data files as runtime input per
  ADR 0001.

## Risks

- Extending the crop helper too broadly could accidentally claim drops for crop
  families not covered by M57 growth. Keep the supported set explicit.
- Carrots and potatoes use crop block ids pluralized from singular item ids. Tests
  should prove namespaced item lookup rather than deriving ids by string surgery.
- Beetroot and nether wart mature at `age=3`, not `age=7`. Keep maturity per block
  id and test both mature and immature boundaries.
- Minimal registries in unit tests may lack some item ids. Missing ids should omit
  only the missing stack, not panic or drop the wrong item.
- Harness drop observation can race pickup. Reuse the M58 mature wheat observation
  pattern and avoid sleeps.
- Deterministic minimum yields are intentionally less generous than vanilla. Keep
  docs and readiness language clear that this is usable farming support, not
  vanilla parity.
