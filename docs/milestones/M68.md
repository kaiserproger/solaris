# M68 - Codebase cleanup from M67 review

**Status:** Closed locally; M68.a through M68.z landed. Branch:
`dev/M68-codebase-cleanup`, stacked after local M67.
**Owning crates:** primarily `mc-net`, with targeted docs/test updates.

## Goal

Reduce feature cost and regression risk before adding more gameplay systems by
cleaning up the highest-value findings from M67.

## Inputs

- `docs/M67_VANILLA_DIVERGENCES.md`
- `docs/M67_CODE_HEALTH_REVIEW.md`
- `docs/M67_TEST_COVERAGE_REVIEW.md`

## Priority Backlog

### M68.a - Plant Lifecycle Policy Extraction

Move plant lifecycle behavior out of the large `play.rs`/`survival.rs`/`item_blocks.rs`
spread into a focused plant policy module.

Scope:

- Extract age growth, stem fruit edits, sapling tree edits, vertical plant
  growth, sweet berry harvest, cocoa placement, and deterministic plant drops
  behind explicit policy helpers.
- Preserve current Solaris behavior exactly.
- Keep deterministic/local behavior visible in names and docs.
- Move or add focused unit tests around the extracted policy.

Non-goals:

- New plant features such as kelp, chorus, mushrooms, or stricter support parity.
- Vanilla loot/RNG changes.

### M68.b - Use-Item-On Interaction Pipeline

Split `handle_use_item_on` into an ordered interaction pipeline with explicit
handled/no-op/place outcomes and centralized ack behavior.

Scope:

- Preserve existing order for containers, beds/toggles, campfires, buckets,
  plant use, bonemeal, and placement.
- Make adding a future interaction require one small handler instead of editing a
  long function body.

Non-goals:

- New interactions or packet layouts.

### M68.c - Container Click Core Deduplication

Refactor duplicated pickup/swap/throw click logic across player inventory,
crafting, furnace, and chest menus.

Scope:

- First write a coverage matrix for menu click modes.
- Add missing focused tests before refactoring if a mode is not covered.
- Introduce a small slot-access adapter or equivalent minimal abstraction.
- Preserve current wire behavior and storage behavior.

Non-goals:

- Faster/specialized smoker/blast furnace behavior.
- Barrel animation parity.

### M68.d - Architecture Drift Note

Record the current async handler/world-lock architecture and how it differs from
the original project spec.

Scope:

- Document which world locks are acceptable today.
- Document what should remain single-writer or main-loop owned.
- Decide whether this is an ADR or a project-spec amendment.

Non-goals:

- Lock-free ownership hardening or M39-level concurrency redesign.

### M68.e - Manual Gate And Coverage Follow-Up

Run or prepare a PrismLauncher manual gate and add one deterministic plant
harness scenario only if it is stable and cheap.

Scope:

- Prefer sweet berry harvest or cocoa placement for deterministic plant harness
  coverage.
- Record any client desyncs or missing packets in the M68 closeout.

Non-goals:

- Timing-dependent random-tick harnesses.

Landed:

- Added deterministic harness coverage for survival sweet berry harvest: mature
  bush use-on resets the block to `age=1` and picks up the berry drop.
- Manual PrismLauncher gate remains owner-run; debug server command is unchanged:
  `cargo run --bin mc-server -- --config example.toml`.

## Closeout

Resolved M67 findings:

- Plant lifecycle policy is no longer scattered across `play.rs`, `survival.rs`,
  and `item_blocks.rs`; growth, deterministic plant drops, sweet berry harvest,
  and cocoa placement policy now live in `crates/mc-net/src/play/plants.rs`.
- `handle_use_item_on` now has explicit `UseItemOnOutcome` dispatch and a
  separate placement helper, preserving the old interaction order.
- Container click packet classification is shared by player inventory, crafting
  table, furnace, and chest handlers; menu-specific slot mutation remains local.
- Runtime world-lock architecture drift is recorded in ADR 0003.
- Deterministic plant harness coverage now includes sweet berry harvest.

Still intentionally open:

- `play.rs` remains large. M68 reduced concentrated hotspots but did not split the
  whole play loop.
- Container slot mutation still has menu-specific duplication. A deeper adapter
  remains future work because result slots, furnace validation, chest persistence,
  and armor slots have different side effects.
- Manual PrismLauncher validation is owner-run.
- Vanilla-exact plant loot/RNG/support parity remains outside this cleanup
  milestone.
