# M34 - Protocol edge-case hardening

**Status:** plan on `dev/M34-protocol-edge-cases` from `main` at local tag
`m33` (`5f474a8`, `fix: apply real entity physics`).
**Owning crates:** `mc-protocol` for packet codecs and oracle-pinned layouts,
`mc-net` for play/configuration state handling and graceful disconnects,
`mc-test-harness` for wire-level compatibility flows, and `docs` for the audit
and closeout checklist.

## Goal

Close protocol gaps that make vanilla 26.1.2 clients fragile outside the happy
path. M34 focuses on packet/state edges Solaris already exercises or must safely
ignore, not broad packet-table completeness.

Every new packet id or field layout must be cited from local oracles under ADR
0002: `.analysis/protocol-dump.txt`, `tools/dump-vanilla-protocol.sh`, or a
`wire-probe` capture against the bundled Mojang server. No packet shape is added
from memory or third-party snippets alone.

## Current Foundation

- Login, configuration, chunk streaming, survival inventory, entities, baseline
  combat, drops, XP orbs, and persistence are sufficient for normal vanilla
  survival smoke flows.
- `mc-protocol` already owns typed codecs for implemented clientbound and
  serverbound packets, but packet coverage has grown opportunistically by
  gameplay slice rather than registration-table audit.
- `mc-net` has state-specific session handling, but malformed or out-of-order
  client packets still need explicit fail-closed coverage instead of relying on
  implicit decode/session behavior.
- `wire-probe` and integration harness flows already exercise happy-path client
  login/configuration/play transitions and can be extended for edge sequences.

## Strategy

1. Audit first. Compare Solaris packet coverage with local Play and
   Configuration registration tables, then pick only packets needed by current
   runtime paths or graceful ignores.
2. Capture before coding when behavior is ambiguous. Use `wire-probe` against a
   vanilla 26.1.2 server for respawn, teleport, resource-pack/status,
   client-settings, chat/commands, and disconnect/error paths.
3. Add narrow codecs with tests pinned to oracle names, ids, and record field
   order. Prefer explicit unsupported/ignored handling over dummy broad codecs.
4. Harden state machines so malformed or out-of-order packets disconnect with a
   clear reason and never panic the server.
5. Keep UX settings safe: honor cheap settings where already useful, and safely
   store or ignore brand, locale, view distance, chat mode, skin parts, and main
   hand without desyncing clients.

## Risks / Pitfalls

- Packet ids and record layouts are version-sensitive. M34 must cite local 26.1.2
  oracles and avoid guessing.
- Broad dummy codecs can hide unsupported features. Add only packets needed by
  current server paths, safe ignores, or deterministic disconnects.
- Client settings may affect chunk streaming pressure. Clamp requested distances
  to configured server limits before applying them.
- Chat, command, and resource-pack protocols contain signed/session fields that
  can be easy to misread. Prefer safe-ignore or explicit unsupported behavior over
  partial semantics.
- Malformed packet tests must exercise real decode/session paths, not synthetic
  helpers that pass by construction.

## M34.b / M34.c Client Settings And Brand Notes

Local oracle sources used for this slice:

```text
.analysis/protocol-dump.txt
.analysis/decompiled/server-26.1.2/net/minecraft/server/level/ClientInformation.java
.analysis/decompiled/server-26.1.2/net/minecraft/network/protocol/common/ServerboundClientInformationPacket.java
.analysis/decompiled/server-26.1.2/net/minecraft/network/protocol/common/custom/BrandPayload.java
.analysis/decompiled/server-26.1.2/net/minecraft/network/protocol/common/custom/CustomPacketPayload.java
.analysis/decompiled/server-26.1.2/net/minecraft/network/FriendlyByteBuf.java
```

The registration-table audit selected the first safe M34 target from common
vanilla UI traffic:

- Configuration `SERVERBOUND_CLIENT_INFORMATION` is id `0x00`.
- Configuration `SERVERBOUND_CUSTOM_PAYLOAD` is id `0x02`.
- Play `SERVERBOUND_CLIENT_INFORMATION` is id `0x0E`.
- Play `SERVERBOUND_CUSTOM_PAYLOAD` is id `0x16`.

The decompiled `ClientInformation` source verifies the field order as
`language`, `viewDistance`, `chatVisibility`, `chatColors`, `modelCustomisation`,
`mainHand`, `textFilteringEnabled`, `allowsListing`, and `particleStatus`.
`FriendlyByteBuf.readEnum` / `writeEnum` use VarInt enum ordinals. The decompiled
custom payload codec verifies that the body starts with an Identifier; the brand
payload uses `minecraft:brand` and one UTF string.

Solaris now decodes these packets in both Configuration and Play. Configuration
logs and ignores them while preserving the existing Known Packs / Finish flow.
Play stores the latest client information for the connection, records optional
brand, and clamps requested view distance to server policy before any future
chunk-streaming use. Current chunk streaming still uses the server-configured
view distance; applying client-requested lower distances remains a later M34
hardening step.

```text
.analysis/decompiled/server-26.1.2/net/minecraft/network/protocol/game/ServerboundClientTickEndPacket.java
.analysis/decompiled/server-26.1.2/net/minecraft/network/protocol/game/ServerboundPlayerLoadedPacket.java
.analysis/decompiled/server-26.1.2/net/minecraft/network/FriendlyByteBuf.java
```

The registration-table audit added the next safe edge packets:

- Configuration `SERVERBOUND_RESOURCE_PACK` is id `0x06`.
- Play `SERVERBOUND_CHAT_ACK` is id `0x06`.
- Play `SERVERBOUND_CHUNK_BATCH_RECEIVED` is id `0x0B`.
- Play `SERVERBOUND_CLIENT_TICK_END` is id `0x0D`.
- Play `SERVERBOUND_COMMAND_SUGGESTION` is id `0x0F`.
- Play `CLIENTBOUND_COMMAND_SUGGESTIONS` is id `0x0F`.
- Play `SERVERBOUND_PLAYER_LOADED` is id `0x2C`.
- Play `SERVERBOUND_RESOURCE_PACK` is id `0x31`.

The decompiled resource-pack status packet verifies `UUID id` then enum ordinal
`Action`. Solaris decodes and logs these statuses in Configuration and Play. No
resource pack is pushed yet, so all statuses are observational safe-ignore.

Command suggestion requests now decode as `VarInt id` plus `readUtf(32500)` and
receive an empty `ClientboundCommandSuggestions` response with the same id. This
does not implement completions, but it closes the UI edge where vanilla clients
can ask for tab suggestions while Solaris only supports a tiny debug command set.
Chat acknowledgements decode one VarInt offset and are safely ignored.

The vanilla lifecycle packets `ServerboundChunkBatchReceivedPacket`,
`ServerboundClientTickEndPacket`, and `ServerboundPlayerLoadedPacket` are now
decoded and safely ignored/noted. Solaris does not yet use the client chunk-batch
rate for scheduling policy, but decoding keeps the Play stream aligned for
vanilla clients that emit these edge packets during load and normal ticking.
