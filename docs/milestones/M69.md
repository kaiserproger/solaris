# M69 - Container click core cleanup

**Status:** In progress locally; M69.a and M69.b landed. Branch:
`dev/M69-container-click-core`, stacked after local M68.
**Owning crates:** primarily `mc-net`, with focused harness/unit tests when a
slot-mutation path lacks direct coverage.

## Goal

Reduce container interaction regression risk by moving the duplicated slot
mutation logic behind a small shared core while preserving current Solaris wire
and storage behavior.

## Inputs

- `docs/M67_CODE_HEALTH_REVIEW.md`
- `docs/M67_TEST_COVERAGE_REVIEW.md`
- `docs/M68_CONTAINER_CLICK_COVERAGE.md`
- M68.c shared `ContainerClickAction` classification in `crates/mc-net/src/play.rs`

## Priority Backlog

### M69.a - Shared Slot Mutation Core

Extract the common pickup/swap/throw mutation mechanics used by player,
crafting, furnace, and chest container clicks.

Scope:

- Introduce the smallest adapter or enum needed to read and write clicked slots
  without duplicating cursor/slot stack movement rules.
- Keep menu-specific side effects local: crafting result consumption, furnace
  result validation, chest persistence, armor/offhand slot mapping, and storage
  bounds.
- Preserve existing packet ack, revision, and storage behavior.
- Add focused unit coverage for any mutation mode whose existing coverage is
  only indirect.

Non-goals:

- New container types.
- Smoker or blast furnace timing/menu parity.
- Barrel animation or block-entity parity.

Landed:

- Added a shared regular pickup/swap/throw slot core used by player inventory,
  crafting table, furnace, and chest click handlers.
- Kept crafting result, furnace result, quick-move, chest persistence, and player
  armor/offhand side effects in their existing menu-specific paths.
- Added focused unit coverage for the shared regular slot core.

### M69.b - Container Coverage Hardening

Close the most useful coverage gaps from the M68 matrix before or alongside the
shared core extraction.

Scope:

- Prefer unit tests for swap/throw behavior in open crafting, furnace, and chest
  windows over broad harness tests.
- Keep harness additions only for externally visible behavior that unit tests
  cannot exercise honestly.
- Update `docs/M68_CONTAINER_CLICK_COVERAGE.md` or add an M69 note if coverage
  materially changes.

Non-goals:

- Exhaustive vanilla parity tests for every click mode.
- Tests that pass by duplicating implementation constants instead of exercising
  real mutation paths.

Landed:

- Extended the crafting table container harness to exercise `Throw` from an open
  crafting window and `Swap` from a hotbar slot into the crafting grid.
- Loaded the real entity-type sidecar in that harness path so throw clicks follow
  the same item-drop gate used by production handlers.

### M69.c - Closeout And Remaining Container Work

Record which duplication was removed and which menu-specific behavior remains
intentionally local.

Scope:

- Run focused container tests and the full workspace baseline.
- Document unresolved follow-ups for specialized furnaces, barrels, and any
  deeper storage abstraction work.
