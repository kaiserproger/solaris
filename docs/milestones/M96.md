# M96 - Multiplayer Survival Soak

**Status:** Planned. Quality label: `stabilization`.

## Agent Start Prompt

Read M94-M95, load scenarios, and the validation ledger. Run preflight.
Run combined multiplayer survival soaks.

## Goal

Exercise integrated gameplay under sustained multiplayer pressure.

## Scope

- Target 2-4 hour debug-server soak where feasible. Degraded fallback is
  at least a 30-minute replayable harness soak with the same action mix.
- Include real clients and/or harness clients, with at least two clients
  for visibility and contention.
- Actions: exploration, block edits, containers, crafting, mobs/combat,
  death/respawn, drops/XP, fluids/plants, save/autosave, disconnect,
  reconnect, slow reader.
- Required assertions: same-block concurrent edits, shared container RMW,
  shared item/XP pickup, disconnect during pending chunk work, bounded
  outbound queue, slow-reader behavior.

## Acceptance

- TPS/tick/memory/lock/queue/chunk latency and correctness outcomes are
  recorded.
- Property/replay corpus is updated; failing seeds produce manifests.
- Shortened/simulated soak says exactly what it failed to prove.

## 2026-07-11 Prompt 02 Block Transaction Slice

Quality label: `stabilization`.

The first Prompt 02 slice replaces implicit read/plan/write block ordering with
an explicit optimistic precondition. Each resident chunk owns a runtime-only
instance id and sparse per-position mutation versions. A pending survival break
captures `(state, chunk instance, version)` at `START_DESTROY_BLOCK`; its later
`STOP_DESTROY_BLOCK` checks that token under the same world lock that applies
the edit. Chunk clones preserve the token, a newly loaded chunk gets a distinct
instance id, and no runtime token enters Anvil data. Normal block placement
uses the same atomic primitive for the clicked support and target-air snapshot;
door placement also guards the upper cell. A concurrent conflict resends both
authoritative blocks and the held stack before ack without consuming it.

`stale_survival_break_cannot_break_peer_replacement` first failed because a
late miner changed peer-placed dirt (`state 10`) back to air (`state 0`). It now
passes both the direct `stone -> dirt` conflict and an ABA
`stone -> dirt -> stone` conflict through two real protocol sessions.
`concurrent_same_target_placements_consume_exactly_one_stack` runs eight
simultaneous dirt-vs-stone rounds and requires exactly one consumed hotbar stack
and a final block matching that winner each round. Focused validation passed
147 `mc-world` tests, 436 `mc-net` tests, and all 66 `block_edit` tests.

The pre-slice M96 bounded replay was also run and remains red for an independent
reason: 128 summon broadcasts did not produce any paused-reader pressure counter
within five seconds. That test currently depends on filling OS/socket buffers
and is not deterministic pressure evidence. No 30-minute soak, save/restart
contention mix, vanilla oracle, or real-client concurrent edit was produced by
this slice.

## 2026-07-12 Outbound Loss Accounting

The old `visibility_command_drops` metric mixed cosmetic arm-animation loss,
reliable backlog overflow and commands discarded after a session closed. The
historical `21720`/`267`/`275` values therefore cannot prove either clean
delivery or reliable data loss and are retired as delivery evidence.

Current telemetry exposes `best_effort_animation_drops` separately from
`reliable_command_drops`. Only arm animation uses the best-effort lane. Spawn,
despawn, movement, block, inventory, container, chat and other state-bearing
commands use the ordered bounded reliable backlog. The synthetic pressure
command now fills the queue with cosmetic animations, and load assertions fail
if reliable backlog overflow increases `reliable_command_drops`.

`mc-net` passes `655/655`; the default load target passes one test with 13
sidecar/load gates explicitly ignored, and the focused embedded playable
multi-client soak passes. No ignored slow-reader or duration soak was rerun in
this slice, so M96 remains non-green.

## 2026-07-12 Tick-Driven Soak Workload

The Prompt 02 soak no longer succeeds after an elapsed wall-clock duration or
schedules work with `tokio::time::interval`. The short and long gates now end
after exactly `400` and `36_000` simulation-tick notifications. Pressure runs
every 100 ticks, liveness every 20, summons every 600, and transaction samples
every 100 or 1,200 ticks. Four bounded client tasks continuously consume socket
frames and answer keepalives; commands wake them through bounded channels.
Session-count waits now subscribe to exact register/unregister events. Wall-clock
timeouts can only fail a stalled gate.

The explicit 400-tick preflight passed with four pressure probes, four checked
transaction samples, 110 entity-spawn observations, 256 cosmetic animation
drops, zero reliable-command drops and a clean final save. Its `24.20 s` runtime
is diagnostic only. The 36,000-tick gate was not run, so the historical
fixed-duration run remains superseded rather than refreshed.
