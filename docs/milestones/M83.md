# M83 - Vehicles And Movement Objects

**Status:** Draft slice implemented. Quality label: `draft`.

## Agent Start Prompt

Read M77-M82 and the validation ledger. Run preflight. Implement vehicles
only if they remain M100 blockers after M77 scope freeze.

## Goal

Provide MVP boats and minecarts or explicitly defer them without
ambiguous readiness wording.

## Scope

- Boats: item spawn, mount/dismount, basic client steering, collision
  bounds, save/restart, two-client visibility.
- Minecarts: placement on rails, mount/dismount, simple rail movement if
  scoped, save/restart, two-client visibility.
- Classify powered rails, chest/furnace minecarts, variants, and complex
  rail physics as implemented, deferred, or non-goal.

## Acceptance

- Vehicle spawn/mount/move/dismount/remove paths have focused tests.
- Real-client evidence confirms scoped paths do not visibly desync.
- Complex vehicle physics is not implied solved.

## Closeout

**Status:** Draft slice implemented. Quality label: `draft`.

M83 landed only the server-domain movement-object foundation in
`mc-entity`. Boats can be represented as vehicle entities with one
passenger, deterministic local steering, position ticking, dismount, and
passenger-removal cleanup. Minecarts can be represented and mounted, but
steering/rail movement returns an explicit unsupported error. No broad
rail, boat water-physics, protocol, persistence, or client-visible parity
claim is made.
