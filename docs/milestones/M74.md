# M74 - Sign editing readiness follow-up

**Status:** Planned locally. Branch: `dev/M74-sign-readiness-followup`,
stacked after local M73.
**Owning crates:** `mc-test-harness`, `mc-net`, `mc-protocol`, and readiness
docs.

## Goal

Reconcile the stale replacement-readiness sign claim after M70 and strengthen the
client-visible sign-editing path with a real wire harness. M70 landed
oracle-backed sign editor/update packets and block-entity updates; M74 verifies
that path from a play client and records the remaining scoped gaps clearly.

M74 is not a new sign feature milestone. It should avoid new protocol claims
unless they are cited from the existing local oracle evidence already recorded in
M70 or from `.analysis/protocol-dump.txt`.

## Priority Backlog

### M74.a - Sign Edit Wire Harness

Add a stable integration test for the M70 sign editing path.

Scope:

- Place a regular sign through the survival/creative block-edit path.
- Assert the client receives `ClientboundOpenSignEditor` for the placed sign.
- Send `ServerboundSignUpdate` with four plain lines for the matching position.
- Assert a `ClientboundBlockEntityData` update arrives for that sign and carries
  the expected plain text shape, without hard-coding protocol ids beyond loaded
  sidecar registry facts.

Non-goals:

- Hanging signs.
- Styled, filtered, clickable, or signed chat text parity.
- Guessing new NBT shapes or packet layouts.

### M74.b - Rejection/Guard Coverage

Cover the server guardrails that keep sign updates scoped to the editor session.

Scope:

- Add focused unit or harness coverage for at least one rejected sign update:
  mismatched position, no pending sign edit, or target block no longer editable.
- Prefer the smallest test that exercises production code without manufacturing a
  success-by-construction packet.

Non-goals:

- A complete malicious-client fuzz matrix.
- Broader command or block-placement permission work.

### M74.c - Readiness Closeout

Update the readiness docs to match the actual post-M70/M74 behavior.

Scope:

- Move sign text editing from deferred to partial support.
- Record the supported path: regular signs, plain four-line text,
  oracle-backed update NBT, and client-visible block-entity update.
- Record remaining gaps: hanging signs, styled/filtered/clickable text, waxed sign
  editing semantics, sign sounds/game events/statistics, and any visual manual
  risks not covered by wire tests.
- Run full workspace gates before closeout.
