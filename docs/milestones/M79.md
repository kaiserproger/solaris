# M79 - Vanilla Oracle Scenario Suite

**Status:** Planned. Quality label: `stabilization`.

## Agent Start Prompt

Read M77-M78, `docs/physics-oracles.md`, `crates/mc-test-harness`, and
the validation ledger. Run preflight. Make vanilla oracle runs systematic
and non-silent.

## Goal

Turn one-off vanilla captures into structured, repeatable oracle
scenarios for M100.

## Scope

- Harden `wire-probe` and parity scenario manifests.
- Add structured facts for block edits, inventory, containers, drops,
  death/respawn, save/restart, and two-client visibility where feasible.
- Add config-phase oracle coverage for KnownPacks, RegistryData,
  UpdateTags, and FinishConfiguration.
- Inventory M43-M47 oracle artifacts: usable, stale, missing, or
  tooling-only.
- Start property/replay corpus for block edits, inventory conservation,
  save/restart idempotence, and malformed packet fail-closed behavior.
- Store captures under `.analysis/` only.

## Acceptance

- At least one vanilla-vs-Solaris scenario produces a clear pass/diff.
- Missing `.analysis/server.jar`, test world, or sidecar reports report
  `degraded` or `blocked`, never silent green.
- The validation ledger links to the oracle scenario classes.

## Implementation Notes

- Added `tools/m79-oracle-scenarios/spawn-smoke.manifest` as the first
  systematic oracle scenario manifest. It points at the existing
  non-flaky `vanilla_and_solaris_spawn_smoke_can_be_diffed` harness test,
  which launches a temp vanilla server and an in-memory Solaris server and
  diffs normalized spawn/start observations.
- Added `tools/run-m79-oracle-suite.sh` to inspect or run manifests and
  write a Markdown report under `.analysis/oracle-suite/`. Missing
  `.analysis/server.jar` blocks vanilla execution; missing
  `data/vanilla/reports` or `.analysis/test-world` degrades the reported
  coverage instead of silently passing.
