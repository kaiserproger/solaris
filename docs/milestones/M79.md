## 2026-07-10 Core Replay Schema Slice

Quality label: `stabilization`.

`mc-test-harness::replay` now defines strict versioned JSON contracts for a
shared core replay scenario and run result. A scenario records a seed, exact
ordered `CoreAction` values, protocol/oracle/real-client execution lanes,
expected invariants, and each lane's required evidence gates. A result records
the selected lane, the same seed and actions, normalized `ObservationSet`
values, gate/invariant outcomes, and full commit/config/build/sidecar/hardware
provenance. Unknown fields and variants fail through serde; semantic validation
rejects empty required sets, duplicate ids, malformed fingerprints or artifact
paths, unexplained non-passing checks, false aggregate outcomes, and
manifest/result mismatches.

The checked fixture
`tools/core-replay-scenarios/core-actions-seed-81.json` contains only portable
scenario metadata and supports future protocol, vanilla-oracle, and real-client
adapters. Focused tests cover parser failures, cross-validation, and fixture
schema/required-field mutations. This slice does not migrate the legacy M79
key/value manifests, execute a parity comparison, or produce fresh oracle
evidence; Q1 and Q3 remain non-green.

## 2026-07-11 Checked-Manifest Real-Client Replay

Quality label: `stabilization`.

The checked seed-81 manifest now drives a real vanilla 26.1.2 client through
the existing repo-native Gradle adapter. `ClientCommands` exposes bounded
`wait_ticks`, `move_by`, and `look` commands; the real implementation waits on
`LocalPlayer.tickCount` and sends the 26.1.2
`ServerboundMovePlayerPacket.Pos`/`Rot` forms from the client connection. The
Python driver rejects incomplete/unknown manifest shapes and unsupported
reconnect before bridge RPCs, records each action and state sample, requires
the requested movement to converge within five centimetres, and writes
`solaris.core_replay.result.v1`. `core-replay-validate` parses and
cross-validates the copied manifest/result pair in `--validate-run`.

The launcher remains fixed:
`tools/run-core-replay-client-gate.sh` delegates to
`tools/run-real-client-regression.sh`, which owns Solaris and invokes
`client-mod/solaris-client-agent/gradlew --no-configuration-cache
:fabric-agent:runClientAgent`. No free-form real-client command hook was added.
The pack copies the canonical manifest into each run directory and defaults to
a fresh per-run world.

The first approved GUI run,
`.analysis/real-client-runs/20260711T023946Z-core-replay-seed-81`, executed all
four actions and produced a schema-valid real-client result, but the outer gate
correctly failed on one `52.940 ms` tick in the inherited mutable test world.
That run is measured blocker evidence, not a passing client gate. After making
the replay world fresh and reproducible,
`.analysis/real-client-runs/20260711T024136Z-core-replay-seed-81` passed the
complete runner validation. The copied manifest is byte-identical to the
checked source; the server persisted movement from `(0.50,81.00,0.50)` to
`(1.50,81.00,0.00)`; the rendered screenshot exists; and the VD8 window
finished in `370 ms` with no slow-stage, degraded-delivery, or server warning.

The result outcome is intentionally `degraded`, not falsely `passed`, because
one real-client phase does not prove repeated-run deterministic normalized
state. This is one narrow real-client wait/move/look/liveness scenario. It does
not make Q2 or Q3 green and does not cover gameplay actions, contention,
save/restart, malformed traffic, broad visual correctness, performance, or
soak.

Focused driver/manifest/replay tests, `./gradlew test --no-daemon`, formatting,
code-health, full workspace tests, and full clippy all passed after the
fresh-world run. The conservative coverage audit remains 46/0 (0.00%).
