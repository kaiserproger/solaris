# M84 - Time, Weather, Sleep, And Dimension Boundaries

**Status:** Planned. Quality label: `draft`.

## Agent Start Prompt

Read M77-M83, bed/respawn/time/weather history, and the validation
ledger. Run preflight. Implement only scoped world-state blockers.

## Goal

Close high-visibility world-state gaps or classify them as non-goals.

## Scope

- Day/night progression and client sync.
- Weather state and rain/thunder sync, or explicit weather-disabled
  policy.
- Beds: sleep enter/exit, occupancy, wake position, single-player time
  skip, multiplayer quorum if feasible.
- Verify or revive `SetDefaultSpawnPosition` and spawn/respawn anchor
  packets from vanilla evidence.
- Portals/dimensions: safe rejection/non-goal or minimal scoped boundary.

## Acceptance

- Bed/time/weather behavior has client evidence or is explicitly not
  claimed.
- Portal/dimension behavior cannot trap or corrupt a client session.
- Readiness docs no longer list sleeping/weather ambiguously.

## Closeout

**Status:** Draft implementation slice. Quality label: `draft`.

M84 landed a bounded world-state slice rather than a full vanilla parity pass.
Solaris now prefers `minecraft:overworld` when selecting the play spawn
dimension, retains the existing `SetDefaultSpawnPosition` join packet, and adds
a deterministic single-player bed sleep path: at Solaris-defined night, using a
bed sets respawn, briefly emits the player's sleeping pose, skips global world
time to the next morning through the in-memory session time state, attempts a
client time update through the existing `ClientboundSetTime` path, then restores
standing pose. Daytime bed use still only sets respawn. Multiplayer bed use sets
respawn and reports that sleep quorum is not implemented. Client-visible time
sync remains degraded because the SetTime clock-map behavior was not proven in
this worktree.

Weather remains explicitly disabled for M84: Solaris does not start rain or
thunder and no new weather packets were added because this worktree lacks the
local protocol oracle artifacts needed to cite fresh packet facts. Full Nether,
End, and portal travel remain a non-goal for the M100 core MVP; the safe boundary
is overworld-only spawn selection and no portal transfer implementation.
