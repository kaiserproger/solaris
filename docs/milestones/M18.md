# M18 - Physics foundation

**Status:** in progress on `main` after local tag `m17` under YOLO mode.
Manual gate remains disabled; automated cargo gates are authoritative for each
slice.
**Owning crates:** `mc-physics` for reusable physics primitives, `mc-entity` for
entity state integration, `mc-net` for adapting snapshots to visible clients,
`mc-world` for block/fluid material queries.

## Goal

Move Solaris from ad-hoc entity Y snapping toward reusable block, fluid, and
entity physics. M18 is a foundation milestone, not full vanilla parity: it
creates the data types and deterministic tick APIs that later survival, combat,
mob spawning, water behavior, and navigation slices can share.

## Strategy

1. Keep physics reusable and deterministic in `mc-physics`; do not bury it in
   Play-session networking code.
2. Model entity bodies with AABBs, velocity, gravity, drag, fluid overlap, and
   ground collision before adding richer block shapes.
3. Keep world access behind material/query seams so tests can exercise real
   behavior without opening sockets or running the server binary.
4. Add vertical slices only when covered by focused unit/harness tests and the
   full cargo gates stay green.
5. Do not guess vanilla constants where exact parity matters. For this first
   slice, constants are Solaris-owned approximations and documented as such;
   later parity work must oracle-pin gameplay constants before claiming vanilla
   identity.

## Target Flow

```text
entity snapshot -> physics body -> material sampler reads nearby blocks/fluids
  -> fixed-tick integration -> collision/fluid result -> entity store update
  -> visibility router sends movement deltas
```

## Sub-Milestones

### M18.a - AABB entity body foundation

Add reusable `mc-physics` types for vector motion, entity AABBs, block material
classes, fixed-tick config, gravity, drag, water buoyancy, and ground collision.

Acceptance:

- Unit tests prove falling bodies land on solid ground.
- Unit tests prove air drag damps horizontal motion.
- Unit tests prove water overlap changes motion with buoyancy and stronger drag.

### M18.b - World material adapter

Connect physics material sampling to `WorldStorage` and block registries for air,
solid blocks, and known terrain fluids.

Acceptance:

- Generated terrain can answer material queries without starting the server.
- Water/lava placed by M17 worldgen are visible to the sampler as fluids.

### M18.c - Entity tick integration

Use the physics step for server-owned mobs instead of direct position stepping
plus post-hoc Y snapping.

Acceptance:

- The cow still spawns/moves for the harness.
- Vertical motion is clamped by ground collision.
- Movement deltas are still based on last sent entity positions.

### M18.d - First block/fluid update seams

Add small deterministic block/fluid tick APIs for gravity-like blocks and static
fluid spread candidates, without claiming full vanilla fluid parity yet.

Acceptance:

- Tests cover sand-like falling intent and bounded water spread intent.
- No world mutation happens outside explicit tick/application APIs.
