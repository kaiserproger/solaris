# M75 - Campfire visual readiness follow-up

**Status:** Planned locally. Branch: `dev/M75-campfire-visual-readiness`,
stacked after local M74.
**Owning crates:** `mc-test-harness`, `mc-net`, `mc-protocol`, and readiness
docs.

## Goal

Reconcile the stale replacement-readiness campfire claim after M70 and strengthen
the wire coverage for campfire block-entity visual metadata. M70 landed
oracle-backed `Items` block-entity updates on insert/completion/clear; M75 should
verify the visible packet path and document exactly what is still out of scope.

M75 is not a furnace-family or hopper/comparator milestone. It should not add new
packet layouts or metadata constants beyond the already-cited M70 oracle evidence.

## Priority Backlog

### M75.a - Campfire Insert Visual Harness

Extend the existing campfire cooking harness to assert the client-visible cooking
input metadata.

Scope:

- After inserting a held campfire-cookable input, assert a
  `ClientboundBlockEntityData` update for the campfire arrives.
- Verify the update tag contains a vanilla-shaped `Items` list with slot `0`, the
  input item id string, and count `1`.
- Keep the harness independent of hard-coded block-entity type ids where possible;
  the packet layout and runtime id are already documented by M70.

Non-goals:

- Smoke, sound, particle, comparator, or hopper parity.
- Client rendering assertions beyond wire-visible block-entity metadata.

### M75.b - Campfire Completion Clear Harness

Cover the visual clear/update path after cooking completes.

Scope:

- Assert a later `ClientboundBlockEntityData` update for the same campfire clears
  the `Items` list after the cooked result is produced.
- Preserve the existing item-entity/pickup assertion so the test still exercises
  real cooking output.

Non-goals:

- Persisting in-flight cooking across restart.
- Exact ejection vector or timing parity.

### M75.c - Readiness Closeout

Update docs to match the actual post-M70/M75 campfire behavior.

Scope:

- Move visual item-on-campfire metadata from unclaimed to partial support.
- Record supported path: insert update, completion clear update, and cooked output
  item entity/pickup.
- Record remaining gaps: in-flight restart persistence, hopper/comparator
  automation, smoke/sound/particle parity, exact ejection vector/timing, and
  broader block-state parity.
- Run full workspace gates before closeout.
