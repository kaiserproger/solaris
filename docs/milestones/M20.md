# M20 - Survival world foundation

**Status:** in progress on `main` after local tag `m19` under YOLO mode.
Manual gate remains disabled; automated cargo gates are authoritative.
**Owning crates:** `mc-worldgen` for terrain/biomes/surface water, `mc-entity`
for mobs and AI state, `mc-protocol` for survival packets, `mc-net` for player
session survival state and world-facing gameplay rules.

## Goal

Replace the temporary flat/plains/demo-cow survival scaffolding with the first
real playable-world foundation: varied land/ocean terrain, biome-aware passive
mob spawning, data-derived placement/survival rules, and no new starter-kit
hardcode. This milestone is still a foundation slice: villages, rich mob AI,
drops, recipes, and combat should land as separate tested sub-slices rather than
one unreviewable blob.

Tellus reference: use the pattern, not the implementation. The useful shape is
large-scale land/water/elevation masks, coastline blending, climate/land-cover
driven biomes, and optional structures/features. Solaris remains offline and
seed-deterministic for now; no OSM/DEM dataset streaming in M20.

## Sub-Milestones

### M20.a - Health and hunger packet oracle

Add the verified clientbound health/food/saturation packet and seed initial
survival state on Play entry.

Acceptance:

- Packet id and layout are cited from protocol dump + `javap`.
- Byte/round-trip tests pin health, food, and saturation encoding.
- Play entry sends initial full health/food state.

### M20.b - Damage state seam

Add server-side player health mutation APIs with clamping, death threshold, and
future damage-source hooks.

### M20.c - Hunger tick seam

Add exhaustion/saturation/food mutation primitives without yet claiming full
vanilla exhaustion parity.

### M20.d - Earth-like biome/ocean terrain

Replace plains-only hill terrain with deterministic large-scale land/ocean masks,
coastlines, beaches, forests, plains, and water-filled ocean columns.

Acceptance:

- Generated chunks over a sampled area contain ocean, beach, forest, and plains.
- Ocean columns place water up to the advertised sea level.
- Login no longer advertises the generated world as flat.
- A missing/empty configured `world_dir` is initialised and pre-generates the
  spawn view window on startup.

### M20.e - Remove starter placement hardcode

Derive item-to-placeable-block resolution from vanilla item/block registries
instead of whitelisting the old starter hotbar items.

Acceptance:

- Any item whose identifier names a registered block resolves to that block's
  default state.
- Non-block items do not place blocks.

### M20.f - Passive herd spawning

Replace the single demo cow with bounded deterministic passive/aquatic spawning
from generated/loaded chunk surfaces and biome JSON `spawners` data.

Acceptance:

- Land creatures spawn only on eligible land surfaces; water ambient/creature
  entries spawn only in water columns.
- Spawning is bounded and does not duplicate on reconnect.
- Entity type IDs and species come from `reports/registries.json` plus biome
  JSON spawn rules, not literals.

### M20.g - Survival loop cleanup

Move remaining debug/starter survival behavior behind explicit data/config or
remove it if not needed for real gameplay.

Acceptance:

- No implicit hardcoded starter kit in normal play.
- Break/place behavior checks gamemode and inventory authority.
- Debug mutation commands are isolated from normal survival rules.

### M20.h - Ore rule data seam

Move generated ore selection from hardcoded branch logic to ordered data-shaped
rules, and parse vanilla placed/configured ore feature JSON into plain data for
future datapack/Lua rule loading. This does not claim vanilla ore parity yet.

Acceptance:

- Current Solaris ore behavior is preserved by default `OreRules`.
- Expanded overworld ore families have targeted tests, including deepslate
  variants and biome-scoped emerald/high gold.
- `mc-data` can parse real vanilla `ore_*.json` placed/configured feature pairs.

### M20.i - Village structure marker seam

Add the first data-backed structure path without claiming vanilla jigsaw parity:
load one local vanilla village template, resolve its palette through Solaris's
block registry, and paste deterministic Solaris-owned marker pieces into eligible
generated grassland chunks.

Acceptance:

- Structure NBT stays local under `data/vanilla`; only loader/rule code is tracked.
- Template block states resolve through `BlockRegistry`, with air/jigsaw/void
  blocks ignored for the first slice.
- Generated chunks paste only intersecting template blocks and refresh heightmaps.
- Server startup enables the marker when the local sidecar template is present.
