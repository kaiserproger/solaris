# M93 - Autoscale Soak And Failure Recovery

**Status:** Planned. Quality label: `stabilization`.

## Agent Start Prompt

Read M92 and the performance/control-plane evidence. Run preflight. Soak
autoscale and failure recovery under pressure.

## Goal

Prove autoscale and control-plane behavior does not silently corrupt or
stall gameplay.

## Scope

- Scenarios: slow disk, chunk-generation storm, reconnect storm, slow
  client, save during shutdown, drain/restart, memory pressure, queue

- Validate low-end, balanced, and high-end profiles.

- Remaining autoscale limits are explicit in docs and ledger.

## Implementer 16 Slice - Bounded Autoscale Soak Reporting

Quality label: `stabilization` with degraded autoscale evidence.

This slice adds `mc_net::AutoscaleSoakReport`, a deterministic report model
for bounded soak/failure-recovery evidence. It consumes existing runtime
primitives only:

- chunk-pipeline policy, resource metrics, and stop reasons such as
  `QueueFull`;
- outbound slow-client pressure counters;
- save-all recovery reports from shutdown/save paths;
- the attempted hardware profile and scenario list.

The report intentionally marks dynamic autoscale as degraded because this
branch has no runtime controller that scales budgets up/down, detects memory
pressure, or applies hysteresis. The implemented evidence is therefore
scaffolding for honest M93/M99 reporting, not a green soak gate.

The snapshot API does not currently accept an M92 controller snapshot. Future
controller evidence must add an explicit typed input instead of inferring
controller behavior from unrelated queue or pressure counters.

### Bounded Scenario Coverage

| Scenario | Current slice result |
|---|---|
| Queue saturation | Represented only when the queue-saturation scenario is attempted and real chunk-pipeline `QueueFull` stop reasons are present. |
| Slow client | Represented only when the slow-client scenario is attempted and real outbound pressure counters are present. |
| Save during shutdown | Represented only when the save-during-shutdown scenario is attempted and a real `SaveAllReport` is captured. |
| Worker saturation/backpressure | Represented by chunk resource max-active counters checked against configured permits. |
| Chunk-generation storm | Reportable as an attempted scenario, but not load-generated by this unit slice. |
| Slow disk | Explicit degraded gap unless a scenario records it. |
| Reconnect storm | Explicit degraded gap unless a scenario records it. |
| Drain/restart | Explicit degraded gap unless a scenario records it. |
| Memory pressure | Explicit degraded gap; no memory-pressure primitive exists yet. |

### Evidence

- Focused test: `cargo test -p mc-net autoscale_soak`.
- The tests exercise the report model against real exported Solaris types
  rather than manufactured pass-only wrappers: `ChunkPipelinePolicy`,
  `ChunkPipelineResourceSnapshot`, `ChunkPipelineStopReason`,
  `OutboundPressureSnapshot`, and `SaveAllReport`.

### Gaps Carried Forward

- No dynamic runtime autoscale controller exists.
- No low-end/balanced/high-end hardware soak was run in this slice.
- No memory-pressure detection or shedding exists.
- Slow disk, reconnect storm, drain/restart, and long chunk-generation storm
  still need live or harness scenarios.
- This does not prove absence of corruption or invisible data loss; it only
  makes bounded evidence and missing primitives visible.
