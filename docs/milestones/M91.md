## 2026-07-12 Off-Tick Percentile Snapshot

The rolling window still records bounded O(1) samples on the simulation ticker,
but percentile allocation and sorting no longer run there. Every reporting
interval the ticker copies the window into a capacity-one queue without waiting;
a `spawn_blocking` worker computes exact nearest-rank percentiles and publishes
the latest completed snapshot. If the worker is still busy, the new window is
skipped instead of delaying simulation and `observer_skipped_windows` increases.
Shutdown drains the accepted request before the ticker exits.

Published telemetry now records the source tick, tick-thread copy cost,
off-thread compute cost and cumulative skipped windows. The explicit 400-tick
runtime gate observed `source_tick=400`, `observer_submit_us=12`,
`observer_compute_us=666`, and `observer_skipped_windows=0`. Autoscale consumes
the latest completed window and may therefore trail by one reporting interval;
it never waits for the observer. `mc-net` passes `658/658` and focused clippy is
clean. This removes the synchronous sorting spike but is not a broad performance
profile or proof that all rare stalls are gone.
