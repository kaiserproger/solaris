# M73 - Loot and drop parity

**Status:** Closed locally. Branch: `dev/M73-loot-drops-parity`, stacked after
local M72. Awaiting owner merge/tag.
**Owning crates:** primarily `mc-data`, `mc-server`, `mc-net`, and
`mc-test-harness`, with readiness docs updated as claims move from deterministic
local behavior to vanilla-backed behavior.

## Goal

Decide and implement the next scoped loot/drop policy step after M72: keep
Solaris deterministic where that is the explicit behavior, but stop hiding behind
repo-owned fallback drops when the local vanilla sidecar already contains simple
loot tables that Solaris can safely load and test.

M73 is not a full vanilla loot-table engine. It targets simple, visible survival
drops that are already expressible by the current one-item `mc-data` loot subset,
then records the remaining RNG/tool/enchantment/table-function gaps explicitly.

## Priority Backlog

### M73.a - Loot Source Policy And Runtime Wiring

Make the server's effective loot source explicit and testable.

Scope:

- Add a minimal config/runtime path for loading simple vanilla loot tables from
  the local sidecar when present, while preserving embedded Solaris loot as the
  no-sidecar fallback.
- Keep Mojang bytes out of the repo; config only points at ignored local data.
- Log whether runtime loot came from embedded Solaris data or the local vanilla
  sidecar and how many simple drops were loaded.
- Cover config parsing/loading behavior without requiring sidecar bytes in CI.

Non-goals:

- Full datapack loading or per-world datapack stacks.
- Committing generated vanilla loot JSON.
- Changing deterministic crop/plant special cases.

### M73.b - Simple Vanilla Loot Coverage Expansion

Broaden `mc-data` coverage for vanilla tables that fit the current simple subset
and expose what is skipped.

Scope:

- Add tests around `load_vanilla_subset` for nested directories, alternatives,
  survives-explosion-only conditions, and unsupported conditions/functions.
- Add summary/inspection helpers if needed so runtime and tests can distinguish
  loaded simple drops from skipped complex tables.
- Preserve the current safe rule: unsupported conditions/functions must not be
  treated as exact vanilla semantics.

Non-goals:

- `set_count`, random rolls, fortune, silk touch, entity killer predicates,
  tool predicates, or explosion decay execution.

### M73.c - Block Drop Harness Coverage

Add real survival wire coverage for one or two non-plant drops that exercise the
effective loot source.

Scope:

- Prefer stone -> cobblestone and one ore -> raw/item drop because they are
  ordinary survival-visible behavior and already covered at unit level.
- Assert real block update, item entity metadata or pickup slot packet, and ack.
- Keep the harness independent of local sidecar availability by using the loaded
  runtime loot path or an explicit in-memory loot config.

Non-goals:

- Silk touch/fortune or exact tool gating.
- Expanding the mining-time/tool model unless the harness reveals a blocker.

### M73.d - Mob Drop Harness Coverage

Tighten configured mob drop/XP claims with a narrow real-wire scenario.

Scope:

- Add or extend harness coverage for one passive or hostile entity drop that
  observes the configured item drop path.
- Keep XP coverage to existing scoped behavior unless a small visible assertion is
  already available in the harness stream.
- Preserve deterministic one-stack mob drops.

Non-goals:

- Looting, killer predicates, equipment drops, baby variants, exact XP ranges, or
  death sounds/statistics/game events.

### M73.e - Drop Policy Closeout

Record which drops are vanilla-backed simple-table behavior, which are still
deterministic Solaris behavior, and what remains for later full loot execution.

Scope:

- Update `docs/REPLACEMENT_READINESS.md` with effective loot source semantics.
- Record unsupported vanilla loot features: RNG/count functions, fortune/silk
  touch, tool/entity predicates, explosion decay, conditions beyond
  `survives_explosion`, and event/stat side effects.
- Run full workspace gates before closeout.

## Acceptance

- Runtime loot source is explicit in config/docs/logging and defaults remain safe
  without a sidecar.
- Existing deterministic plant/crop drops do not accidentally change.
- New or updated harness coverage exercises real packet/client-observable item
  drops, not constructed pass-by-construction data.
- Unsupported vanilla loot-table features are skipped or documented, not silently
  misrepresented as parity.

## Closeout Notes

- Runtime loot source is explicit: no configured sidecar uses embedded
  repo-owned Solaris loot; a configured local sidecar is used only when the
  simple vanilla subset loader finds at least one loadable drop.
- The vanilla sidecar subset accepts one-item drops, nested directories,
  alternatives, and `minecraft:survives_explosion` conditions. Any loot
  functions or other conditions are skipped rather than treated as parity.
- Survival wire coverage now checks stone to cobblestone through configured
  block loot and a passive mob configured drop that differs from fallback loot.
- Remaining gaps are intentionally deferred: full loot-table execution,
  `set_count`/random rolls, fortune/silk touch, tool/entity predicates,
  explosion decay, looting, equipment drops, exact XP ranges, and
  sounds/particles/statistics/game events.
