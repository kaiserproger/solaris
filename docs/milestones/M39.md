# M39 - Lock-free server hardening

Status: reserved follow-up from M35 closeout. This is not the full M39
implementation plan; write the normal milestone plan on the M39 branch before
coding.

## Directive

The server should be as lock-free as practical. Locks that remain must be small,
bounded, and never held across disk I/O, worldgen, network writes, command
dispatch, or long player/session scans.

## Required scope

- Audit `WorldStorage`, chunk streaming, save paths, session/player registries,
  entity runtime state, command/admin operations, and test harness frame drains
  for long-held mutexes or lock-order hazards.
- Replace hot global locks with one of: immutable snapshots, message queues,
  sharded ownership, actor-style workers, or narrow per-resource locks.
- Keep generated/chunk prepare work outside storage locks. M13/M33 reduced some
  stalls, but M39 should treat that as the starting point, not the finish line.
- Add regression tests or tracing assertions for the paths changed by the pass;
  avoid fake tests that pass by construction.

## Acceptance sketch

- Interactive play, chunk streaming, command dispatch, save-all, and shutdown do
  not hold global locks across blocking work.
- Harness races caused by raw frame drains are replaced with buffered/filtered
  helpers where they intersect server lock validation.
- `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D
  warnings`, and `cargo fmt --all -- --check` remain green.
