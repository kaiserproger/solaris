# M19 - Commands and player state foundation

**Status:** in progress on `main` after local tag `m18` under YOLO mode.
Manual gate remains disabled; automated cargo gates are authoritative.
**Owning crates:** `mc-protocol` for verified command/player-state packets,
`mc-net` for command routing and per-session state, `mc-test-harness` for wire
coverage.

## Goal

Start the vanilla server command and player-state surface needed by creative
mode, OP/admin flows, and the later survival loop. M19 does not attempt the full
Brigadier command tree in one pass; it first makes typed serverbound command
packets, gamemode state, and local OP-like permission seams real and tested.

## Strategy

1. Oracle-pin every packet id and layout from `.analysis/protocol-dump.txt` and
   `javap`; do not guess command packet shapes.
2. Keep command execution server-authoritative and session-local first.
3. Prefer a tiny real command executor over fake test-only hooks.
4. Use `GameEvent(CHANGE_GAME_MODE)` for immediate client-visible gamemode
   switching, then add command-tree/client UX later.
5. Keep permission semantics explicit: local dev sessions are OP-capable until a
   persisted ops list lands.

## Sub-Milestones

### M19.a - Protocol packet oracle

Add typed packets for serverbound chat commands and client-requested gamemode
changes.

Acceptance:

- Packet ids are cited from `GameProtocols` order.
- Field layouts are cited from `javap`.
- Byte/round-trip tests pin the wire shape.

### M19.b - Gamemode command foundation

Add session gamemode state, parse `/gamemode <mode>` from serverbound command
packets, and send `GameEvent(CHANGE_GAME_MODE)` to the client.

Acceptance:

- `/gamemode creative`, `/gamemode survival`, `/gamemode adventure`, and
  `/gamemode spectator` parse.
- Numeric modes `0..3` parse.
- Invalid modes are rejected without changing state.
- Harness/unit coverage verifies emitted game-event mode changes.

### M19.c - OP/admin seam

Introduce an explicit permission check so command execution no longer assumes
every future player can change gamemode.

Acceptance:

- Current local/dev profiles are OP-capable by config/default.
- The check is isolated so a persisted ops list can replace it later.

### M19.d - Player abilities / creative usability

Add the verified clientbound player-abilities packet and send creative/spectator
ability changes when gamemode changes.

Acceptance:

- Packet layout is oracle-pinned.
- Creative mode grants mayfly/instabuild/invulnerable semantics on the client.
