# M67 - Codebase-wide review

**Status:** Closed locally; M67.a through M67.z landed. Branch:
`dev/M67-codebase-wide-review`, stacked after local M66.
**Owning areas:** whole workspace for review; `docs` for findings and M68
cleanup backlog.

## Goal

Stop adding gameplay slices long enough to review Solaris as a replacement
server and as a Rust codebase. The output is a prioritized, written cleanup and
parity backlog for M68+.

## Scope

- Enumerate known behavior divergences between Solaris core gameplay/runtime and
  vanilla 26.1.x, separating intentional scoped behavior from replacement-risk
  gaps.
- Review the codebase for duplicate code, dead code, one-use helpers that make
  call sites harder to read, and unnecessary module coupling.
- Review test coverage shape: where unit-only coverage is acceptable, where a
  harness or oracle-backed test is warranted, and where tests assert too little.
- Write findings with concrete file/function references and proposed cleanup
  ordering.
- Produce the M68 cleanup backlog from the M67 findings instead of mixing review
  and cleanup in one milestone.

## Non-Goals

- Large refactors or cleanup implementation.
- New protocol or vanilla metadata claims without local oracle evidence.
- Re-litigating milestone history unless it identifies current risk.
- Push, merge, or tag.

## Strategy

1. Build the behavior-divergence list from `docs/REPLACEMENT_READINESS.md`,
   milestone closeouts, harness coverage, and high-risk gameplay modules.
2. Review code structure across `mc-net`, `mc-world`, `mc-data`, `mc-server`,
   and `mc-test-harness`, prioritizing hot/large modules and recent plant/combat
   slices.
3. Record findings in review-focused docs with severity, affected files,
   suggested remediation, and whether M68 should handle it.
4. Close M67 by writing `docs/milestones/M68.md` as the cleanup plan/backlog.
