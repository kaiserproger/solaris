# M42 - Lock-free ownership rewrite

**Status:** agent-side closeout on `dev/M42-lock-free-ownership`, branched from
local M41 recovery head `8b85e97` (`feat: M39-M41 manual recovery hardening`).
Manual PrismLauncher validation remains owner-run per repo workflow.
**Owning crates:** `mc-net` for session/play/save orchestration, `mc-world` for
storage flush and chunk snapshot boundaries, `mc-test-harness` for race/load
coverage, and `mc-server` only where runtime wiring is required.

## Goal

Remove the long global critical sections that can stall interactive play while
chunks stream, saves flush, entities tick, commands dispatch, or players
disconnect/reconnect.

M42 does not mean "no locks anywhere." It means no hot global lock is held across
disk I/O, region rewrites, world generation, packet writes, long session scans,
or blocking save paths. Any remaining lock must be narrow, measured, and justified
in the closeout.

## Current Foundation

- M39 added lock wait/hold instrumentation and exposed lock pressure in runtime
  metrics.
- M40/M41 added dispatch counters and found manual symptoms that can be confused
  with TPS/lock stalls.
- Current known blockers from review remain:
  `WorldStorage::flush_dirty` still rewrites region files while the world mutex is
  held; chunk prepare can still load/decode chunks under the world mutex; save-all,
  `/stop`, console save, and shutdown still share a synchronous save path; and
  session registry scans still depend on one monolithic mutex.
- Existing automated gates are green, but green tests do not prove lock-free
  behavior unless the lock counters and race harnesses are asserted.

## Strategy

1. Preserve M39 metrics and use them as the before/after oracle for each slice.
2. Move expensive work outside locks before introducing new ownership machinery.
3. Prefer explicit snapshot/commit phases over broad actors unless ordering becomes
   unmanageable.
4. Make save/shutdown one bounded pipeline with explicit completion reporting.
5. Keep protocol ordering from M36-M41: visibility, container, pickup, and command
   dispatch must remain per-viewer correct.
6. Do not hide races by draining harness frames; buffer unmatched frames when a
   test needs later packet assertions.

### M42.b - Flush planning outside the world lock

Split dirty chunk persistence into plan, write, and commit phases.

Acceptance:

- `WorldStorage` can build a bounded dirty flush plan under the world lock.
- Region file reads/writes/renames happen outside the world mutex.
- Dirty state is marked clean only after the corresponding write succeeds.
- Dirty chunks touched after the plan was built remain dirty.
- Persistence tests still prove block edits, block entities, scheduled ticks,
  entities, player data, and world metadata survive restart.

### M42.c - Bounded save pipeline

Route `/save-all`, console save, Ctrl-C, and `/stop` through one save coordinator.

Acceptance:

- Save requests are queued or coalesced instead of running all persistence inline
  on the caller's hot path.
- Save reports still include players, entities, chunks flushed, world metadata,
  elapsed timings, and errors.
- Shutdown waits for a bounded final save phase and then tears sessions down
  cleanly.
- A slow chunk flush does not block keepalive handling or unrelated player packet
  reads longer than the documented critical-section budget.

### M42.d - Chunk snapshot pipeline

Move chunk streaming and prepare work away from repeated global world-lock holds.

Acceptance:

- Chunk streaming obtains immutable chunk snapshots or prepare jobs with short
  lock-held phases.
- Disk I/O and generation are not performed while holding the shared world mutex.
- Commit of generated chunks validates that the target chunk is still absent or
  otherwise safe to replace.
- Exploration tests still assert correct chunk/light delivery and movement across
  chunk boundaries.

### M42.e - Simulation snapshots

Ensure entity physics, scheduled ticks, and fluid/random simulation do not scan or
load unrelated chunks under one long lock.

Acceptance:

- Entity physics samples only loaded/cached snapshots and never triggers generation
  from inside a hot server lock.
- Scheduled fluid/block tick draining has bounded per-tick work and reports backlog
  separately from lock contention.
- Random tick sampling keeps the existing chunk budget behavior.
- Mob movement, drops, pickup, and fluid tests still pass through real play paths.

### M42.f - Session registry dispatch plans

Split long session scans and packet dispatch away from the session registry mutex.

Acceptance:

- Visibility, broadcasts, entity dispatch, pickups, container viewer updates, and
  command feedback build small immutable dispatch plans under the lock.
- Packet sends and expensive per-viewer work happen after releasing the registry
  lock.
- Nested session/player-persistence locks have one documented order or are removed.
- Multi-client tests still prove visibility, shared pickups, block edits,
  containers, reconnect, and duplicate profile handling.

### M42.g - Harness buffering for race coverage

Replace drains that can hide M42 races with buffered frame helpers.

Acceptance:

- `mc_test_harness::client::Client` can wait for packet ids without discarding
  unrelated frames needed later.
- Existing tests are migrated only where raw drains affect ownership/race coverage.
- Buffered helpers preserve packet order and keep timeouts explicit.
- Tests still use real TCP and protocol codecs.

### M42.h - Lock-pressure regression gates

Acceptance:

- Focused tests or ignored load scenarios report before/after lock pressure for

- Slow-lock warnings are absent or explained in the closeout for the manual gate.

## Risks / Pitfalls

- Snapshot/commit phases can lose writes if dirty state is marked clean too early.
- Moving work outside locks can introduce stale chunk/session decisions.
- Save coalescing can report success for work that only got queued.
- Actors can make ordering harder to prove than narrow locks; use them only where
  they simplify ownership.
- Race tests can pass by consuming the packet that should have been asserted later.

## Implementation Notes

- First M42.b slice splits dirty chunk persistence into plan, write, and commit
  phases. Planning encodes dirty cached chunks while the caller still has a
  consistent world snapshot; region read/write/rename happens through the owned
  plan after the outer world mutex is released; commit reacquires storage only to
  clear chunks whose current encoded payload still matches what was written.
- `save_all` now measures the short plan and commit phases under
  `SaveAllFlush`; the potentially slow `.mca` rewrite is outside the
  `WorldHandle` mutex.
- Added a storage regression for chunks edited after planning: commit must not
  clear dirty state for newer payloads, and the next flush must persist the new
  state.
- Dirty LRU cache eviction no longer calls `flush_dirty` from inside chunk
  insertion. Clean chunks are evicted first; if every resident chunk is dirty,
  the cache may temporarily exceed its configured capacity until the save
  pipeline commits dirty chunks clean.
- First M42.g harness slice adds a buffered packet-id wait helper to
  `mc_test_harness::client::Client`. The command harness now uses it for
  command feedback and time updates, preserving unrelated frames for later
  assertions instead of draining them.
- Save requests now pass through one coordinator (`SAVE_COORDINATOR`) before
  running persistence. The queue is intentionally simple: it serializes
  `/save-all`, console save, `/stop`, and shutdown save requests without adding a
  broader actor or changing command semantics.
- `SaveAllReport` now carries elapsed timings for queue wait, player save,
  entity save, metadata save, flush plan/write/commit, and total save time.
- Chunk streaming uses `ChunkSnapshotPlan` to separate short world-lock snapshot
  phases from disk region read/decode. Generated chunk work was already outside
  the lock; commit remains a short validation/insert phase.
- Random tick sampling and scheduled fluid tick draining now read cached chunks
  only, avoiding generation or disk load from simulation paths. Entity physics
  already used cached samples only and remains covered by tests.
- Session registry packet dispatch already followed the plan/dispatch split for
  visibility, entity movement, pickups, furnace/chest viewers, and command
  feedback. M42 kept that model and verified with multi-client harness tests.

Remaining global locks and reason to keep them:

| Lock | Status | Reason |
|---|---|---|
| `WorldHandle = Arc<Mutex<WorldStorage>>` | hot but narrowed | Protects mutable chunk cache, dirty state, block entities, scheduled ticks, and generator commits. No region rewrite, chunk disk decode, or world generation is intentionally performed while held. |
| `SessionRegistry::inner` | hot but narrow | Protects active session maps, visibility sets, entity registry, viewer maps, tickets, and prepared chunk cache. Methods build immutable dispatch vectors and send after dropping the lock. |
| `PlayerPersistedState` mutex | cold/narrow | Per-player persisted state snapshot/update lock; never nested outside the documented session snapshot paths in this slice. |
| `SAVE_COORDINATOR` | cold queue | Serializes explicit save requests so repeated `/save-all`, `/stop`, console save, and shutdown saves do not run overlapping persistence pipelines. |
