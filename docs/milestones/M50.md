# M50 - Session, entity, and physics scalability

**Status:** draft plan for owner review. Proposed branch:
`dev/M50-session-entity-scalability`, cut from `main` after the preceding
milestone tag.
**Owning crates:** `mc-net` for session registry, visibility, play loop, and
physics orchestration, `mc-entity` for entity data layout and lightweight views,
`mc-physics` for sampler contracts, and `mc-test-harness` for multicore and
slow-client coverage.

## Goal

Remove the hot `SessionRegistry` serialization points and allocator-heavy entity
physics pipeline while preserving existing gameplay behavior.

M50 is the gameplay-state scalability milestone. It should make player movement,
entity visibility, and physics candidate selection scale by affected chunks and
entities, not by all sessions and all entities under one blocking mutex.

## Scope

- Chunk-indexed player/entity visibility diffs.
- Lightweight entity views for physics, visibility, and persistence separation.
- Physics material table caching and allocation reduction.
- Reliable vs lossy outbound backpressure lanes.
- Play-loop fairness under outbound bursts.

## Non-Goals

- Full mob AI rewrite.
- Entity-vs-entity collision parity; route to a physics/parity milestone if needed.
- World storage sharding; M49 owns world snapshots/locks.
- Protocol compression internals; M51 owns frame/buffer work.

## Current Bottlenecks

- `SessionRegistry` is one `std::sync::Mutex` and `refresh_visibility_locked`
  rebuilds visibility for all observers/entities.
- Movement updates call visibility refresh from the hot play path.
- Entity physics query selection clones full `EntitySnapshot` values and sorts all
  candidates to take a small budget.
- Physics sampling allocates per-entity `Vec<BlockPos>` and
  `HashMap<BlockPos, BlockMaterial>`, then clones batches for workers.
- `try_send` drops authoritative state commands when outbound queues are full.
- The play loop uses biased select with outbound command handling before inbound
  reads.

## Strategy

1. Separate data needed for hot-path simulation from persistence-grade snapshots.
2. Index visibility by chunk and update incrementally on chunk/session/entity moves.
3. Keep locks short: collect minimal facts under lock, build dispatches outside.
4. Make physics sampling use cached read-only tables and move-owned worker batches.
5. Treat movement updates as lossy/coalescible, but block/light/container/entity
   lifecycle updates as reliable or replayable.

## Sub-Milestones

### M50.a - Lightweight Entity Views

Acceptance:

- `mc-entity` exposes borrowed or copy-light iterators for physics and visibility
  without cloning `String`, `AttributeSet`, or `GoalState`.
- Persistence continues to use full `EntitySnapshot` where needed.
- Entity type facts or AABBs are cached by type instead of reparsed from strings in
  the tick hot path.
- Existing mob, item pickup, and persistence tests remain green.

### M50.b - Incremental Chunk Visibility

Acceptance:

- Player and entity visibility are indexed by chunk or chunk ticket set.
- Player movement updates diff only affected old/new chunk neighborhoods.
- Entity spawn/move/remove updates only affected observers.
- `refresh_visibility_locked` is removed from hot movement paths or restricted to
  explicit full-rebuild repair/debug paths.

### M50.c - Physics Pipeline Allocation Reduction

Acceptance:

- `BlockMaterial` classification is precomputed once in server config or runtime
  resources.
- Physics worker batches move owned inputs instead of cloning per-entity sample
  maps.
- Per-entity sampled blocks use compact storage or pre-reserved maps.
- `BlockSampler` no longer requires `&mut self` unless a concrete sampler needs
  interior mutability.

### M50.d - Session Lock and Dispatch Split

Acceptance:

- Entity goal ticking, physics query collection, and physics result application hold
  the session lock only for state mutation/fact collection.
- Expensive sorting/filtering/dispatch construction happens outside the lock where
  possible.
- Any remaining `self.inner.lock()` direct calls route through lock metrics.
- Session lock max hold improves under the M48/M49 multicore load gate.

### M50.e - Outbound Backpressure and Play Loop Fairness

Acceptance:

- Outbound commands are classified into reliable/replayable/coalescible lanes.
- Reliable state transitions are not silently dropped on full queues.
- Movement/light/block bursts are coalesced by key where practical.
- The biased play-loop select is removed or bounded so inbound reads get regular
  progress under outbound pressure.

### M50.f - Slow-Client and Visibility Load Gate

Acceptance:

- Add a harness probe with one slow or paused reader and one active client causing
  entity/block/chunk broadcasts.
- The active client remains responsive within a documented timeout.
- The test asserts no unbounded queue growth and reports lock pressure.
- Existing two-player presence tests remain green.

### M50.g - Closeout

Acceptance:

- Document new visibility/indexing invariants.
- Record lock/allocation risks that remain in entity AI or physics.
- Baseline validation passes.

## Risks

- Visibility indexes are correctness-sensitive; missed invalidation causes ghost
  players/entities.
- Reliable queues can turn slow clients into memory pressure if not bounded and
  coalesced.
- Physics allocation cuts must not change collision/fluid behavior without an
  oracle-backed parity milestone.
