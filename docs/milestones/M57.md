# M57 - Crop growth and bonemeal

**Status:** M57.a committed; M57.b landed locally; M57.c pending. Branch: `dev/M57-crop-growth-bonemeal`, cut from `main` after M56 closeout.
**Owning crates:** `mc-net` for crop random ticks, bonemeal use, held-stack updates, and block edits; `mc-data` only if a tiny block-facts helper is needed; `mc-test-harness` for survival coverage; `docs` for readiness updates at closeout.

## Goal

Make basic overworld farming feel complete enough for survival play: common planted
crops continue growing after placement, and bonemeal can visibly advance them
without requiring new protocol layouts.

This builds on the existing crop placement, farmland moisture, farmland trample,
random tick, block update, inventory slot sync, and harness block-edit paths. It
closes a visible replacement-readiness gap while avoiding GUI, entity metadata, or
clientbound effects work.

## Scope

- Extend crop random ticks beyond wheat to the common age-based crops Solaris can
  already place: `minecraft:wheat`, `minecraft:carrots`, `minecraft:potatoes`,
  `minecraft:beetroots`, and `minecraft:nether_wart`.
- Add server-side bonemeal handling through the existing `ServerboundUseItemOn`
  path when a player uses `minecraft:bone_meal` on one of those crops.
- Consume exactly one bonemeal only when the crop can advance.
- Advance crops by deterministic Solaris rules that preserve vanilla data state
  shapes: random ticks and bonemeal each increase age by exactly one step up to
  the crop's maximum registered `age` state.
- Send existing block update and held-slot sync packets after successful bonemeal
  use.
- Keep behavior covered by focused unit tests first, then a non-ignored Solaris
  harness survival test.

## Non-Goals

- Vanilla RNG parity for crop growth or bonemeal growth amounts.
- Bonemeal particles, sounds, game events, hand animation parity, or clientbound
  level-event effects.
- Harvest/drop table parity, fortune, replant automation, composters, bees,
  villager farming, or water/sunlight growth-rate parity.
- Stem crops, cactus, sugar cane, bamboo, kelp, chorus plants, cocoa, sweet berry
  bushes, or tree/sapling growth in M57.a.
- New packet IDs, new packet field layouts, or guessed entity/block metadata.

## Strategy

1. Keep M57.a on already verified network paths: `ServerboundUseItemOn`, block
   updates, acknowledgements, inventory/slot sync, and existing random tick edits.
2. Replace the wheat-only growth helper with a small age-based helper that reads
   the current block state's `age` property and asks the block registry for
   `age + 1` on the same block id.
3. Restrict M57.a to simple planted crops that use only the `age` property for
   growth. If a block lacks a next age state, treat it as mature and do nothing.
4. Add bonemeal handling before normal placement in `UseItemOn`: require the held
   item to be `minecraft:bone_meal`, require a targeted growable crop, advance the
   block state, decrement the held stack, sync the slot, and stop normal placement.
5. Use deterministic growth increments for Solaris: random ticks and bonemeal both
   advance by exactly one age. Larger vanilla-like bonemeal jumps remain deferred.
6. Add harness coverage only after the pure helper and packet-path tests are
   stable. The harness should assert visible block state changes and item
   consumption, not particles or sounds.
7. Update `docs/REPLACEMENT_READINESS.md` only at closeout with the exact farming
   claim that landed.

## Sub-Milestones

### M57.a - Age-based crop growth and bonemeal vertical slice

Landed locally:

- In `mc-net`, generalize the existing `next_crop_growth_state` helper so it can
  advance any supported age-based crop by looking up the current block id and its
  current `age` property, then resolving the same block id with `age + 1` through
  `BlockRegistry::by_name_and_props`.
- Restrict the helper to this explicit supported set for M57.a:
  `minecraft:wheat`, `minecraft:carrots`, `minecraft:potatoes`,
  `minecraft:beetroots`, and `minecraft:nether_wart`.
- Keep random ticks advancing by one age and returning `None` at maturity or for
  unsupported crop-family blocks.
- Add `UseItemOn` handling for `minecraft:bone_meal` against those same crops:
  if the crop can advance, update the block state through the existing edit path,
  decrement one held bonemeal, send the normal slot update/ack path, and do not
  continue into normal block placement.
- If the crop is mature, unsupported, out of reach, not loaded, or the held stack
  is not bonemeal, do not consume bonemeal.
- Add focused `mc-net` tests for wheat, carrots, potatoes, beetroots, and nether
  wart growth; maturity no-op; unsupported crop-family no-op; bonemeal consumes
  exactly one item only on successful growth.

Deferred from M57.a: particles, sounds, level events, vanilla RNG/growth-rate
parity, and harness coverage.

Acceptance:

- Placed carrots, potatoes, beetroots, wheat, and nether wart can advance through
  their registered age states without hardcoded protocol state IDs.
- Mature crops are stable and do not consume bonemeal.
- Bonemeal use produces a visible block state change and held-stack decrement via
  existing packet paths.
- Existing wheat growth, crop placement, farmland moisture, farmland trample,
  campfire, shield, combat, and inventory tests remain green.
- No new packet IDs, field layouts, metadata, sounds, particles, or level-event
  packets are introduced.

Suggested focused gate:

```sh
cargo test -p mc-net crop -- --nocapture
cargo test -p mc-net bonemeal -- --nocapture
cargo fmt --all -- --check
```

Passed locally after M57.a.

### M57.b - Survival harness coverage

Landed locally:

- Add `block_edit` harness test
  `bonemeal_grows_young_crop_once_and_mature_crop_does_not_consume`.
- The test sets up farmland plus young and mature wheat in the Solaris world,
  gives the client bonemeal, then verifies young wheat advances from age 0 to
  age 1 and the held stack decrements from 2 to 1.
- The same test targets mature wheat and verifies there is no block update and
  no bonemeal consumption before the interaction ack.
- Like the existing Solaris harness, the test requires the vanilla data sidecar
  but does not require `.analysis/server.jar`.

Acceptance:

- Add a non-ignored Solaris-only harness test under `block_edit` or an adjacent
  farming module.
- Test setup gives the client farmland/soil as needed, one supported crop seed or
  item, and bonemeal.
- The test places or targets a supported crop, uses bonemeal, observes the held
  bonemeal stack decrement, and observes the crop block state advance.
- Include a mature-crop or unsupported-target control that proves bonemeal is not
  consumed when no growth happens if the harness can set the state directly using
  existing helpers.
- The test does not require `.analysis/server.jar`.

Suggested focused gate:

```sh

```

## Protocol and Data Oracles

- M57.a must not add new packet IDs or field layouts. It should reuse existing
  verified `ServerboundUseItemOn`, block change/ack, inventory slot sync, random
  tick, and block edit paths.
- Vanilla data sidecar is required for block and item registries. Crop state
  advancement must resolve registered block states by namespaced block id and
  `age` property rather than hardcoded numeric state IDs.
- No vanilla oracle capture is required for M57.a if particles, sounds, level
  events, and metadata remain deferred.
- If a later slice attempts bonemeal particles/sounds, exact clientbound level
  events, or vanilla RNG/growth amount parity, first capture the behavior with
  `wire-probe`/`.analysis/server.jar` and cite the dump per ADR 0002.

## Risks

- Some crop-family blocks in `BlockFactsTable` are not simple age-only crops.
  Keep M57.a on the explicit supported set instead of broadening by family.
- Bonemeal handling could accidentally consume items on mature or unsupported
  targets. Unit-test the consume/no-consume boundary before adding harness
  coverage.
- Random tick tests can become brittle if they assume numeric state IDs from the
  real sidecar. Use test registries or resolve states by id/properties.
- Harness assertions may race block updates and slot sync. Wait for the existing
  ack/block-change path rather than sleeping.
- Nether wart grows on soul sand and has different age bounds; rely on registry
  lookup for the next state and do not special-case numeric caps unless tests show
  the registry lacks a direct next age.
