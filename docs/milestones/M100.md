# M100 - Core Validation Decision

**Status:** Planned. Quality label: `release-ready` only if every required
row is green; otherwise `stabilization`.

## Agent Start Prompt

Read M77-M99, `docs/DEFINITION_OF_DONE.md`, the validation ledger,
readiness docs, operator docs, and all M99 artifacts. Run full preflight.
Validate readiness; do not create readiness by assertion.

## Goal

Decide whether the scoped core MVP is release-ready, with brutal evidence,
or produce the M101+ blocker list.

## Required Evidence

- Preflight: DoD preflight plus port, `.analysis/test-world`,
  `.analysis/server.jar`, vanilla sidecar, branch, dirty status.
- Cargo baseline after final change: `cargo fmt --all -- --check`,
  `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`.
- Focused harness: protocol/session, chunks, lighting, block edits,
  fluids, farming, loot, inventory, containers, block entities, entities,
  combat, death/respawn, persistence, multiplayer, load.
- Vanilla oracle for every mechanic counted toward coverage.
- Real vanilla/PrismLauncher client for the complete scoped manual matrix.
- Property/replay corpus with seed manifests for failures.
- Performance for low-end, balanced, and high-end profiles.
- Concurrency evidence: no blocking disk/worldgen/network writes under
  long locks; slow reader cannot stall healthy clients; save/stop/
  reconnect/chunk work does not corrupt state.
- Generated-world join/chunk-stream evidence: starting from an empty
  `example.toml` world or a fresh generated-world fixture, Solaris must
  generate, persist, restart/open, and stream the view-distance-8 spawn
  window with no missing/extra/duplicate chunks and with green recorded
  budgets for first/ring/full chunk latency, tick p95/p99, lock wait/hold,
  `fetch_ms`, `light_compute_ms`, dirty flush pressure, and worker/queue
  saturation. The M77 baseline of 17.3s full-window stream plus repeated
  tick/`chunk_prepare` warnings is explicitly non-green.
- Autoscale evidence: predictable degradation, decision logs, no
  oscillation, no silent corruption.
- Persistence/crash evidence for players, chunks, entities, block
  entities, containers, scheduled ticks, time, weather where scoped.
- Docs match evidence: readiness, operator docs, and validation matrix.

## Acceptance

- `release-ready`: all required in-scope ledger rows green, scoped
  coverage >=80%, no high-severity real-client/manual blockers,
  performance/concurrency/autoscale budgets green.
- The generated-world join/chunk-stream row cannot be waived silently. If
  it still has unexplained tick-budget, `chunk_prepare`, `save_all_flush`,
  or full-window latency misses, M100 is `stabilization` unless the owner
  explicitly accepts the degradation as non-release-ready debt.
- Owner-accepted budget misses are non-green degradations unless the
  report proves they do not affect release safety.
- Accepted non-goals/divergences are excluded from the 80% numerator and
  required-green rows, but remain visible in docs.
- `stabilization`: any required evidence is missing, degraded, manual-
  pending, oracle-missing, blocked, or not run.
- No M0-M76 deferred debt may be silently absent from the final matrix.
