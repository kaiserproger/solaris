# M7 — Worldgen baseline

**Status:** plan only, on `dev/M7-worldgen-baseline` (0 commits
ahead of `main` at `1620aaf`, tag `m6`).
`cargo test --workspace` baseline is 226 tests green.
**Estimate:** scope-bounded MVP — 30-60 h. Option **B** of the M6
kick-off menu, intentionally trimmed: spec §9 calls M4 worldgen
"120-180h" assuming biomes + structures + parity-ish noise. Solaris
ships a *baseline* in M7: a single-biome, no-structures, no-caves
hilly terrain that lets the player walk to any chunk position and
see solid ground. Biome variety, caves, structures, ores — all M9+.
**Owning crates:** `mc-worldgen` (currently a stub) grows a small
noise primitive + a `TerrainGenerator` that produces a fully-formed
`Chunk` from `(ChunkPos, seed)`; `mc-world::WorldStorage` learns to
fall back to a generator when the region file doesn't cover the
requested chunk; `mc-server` wires the generator (and a seed) into
the world handle from config; `mc-test-harness` pins a "walk
beyond the test world" integration scenario.

## Goal

After M7 a vanilla 26.1.2 player on a fresh, empty `world_dir`:

1. Connects and lands on solid ground at a reasonable spawn Y.
2. Sees terrain in every direction — no air-only chunks, no
   "void wall" at the edge of the bundled test region.
3. Walks 200 blocks in any direction. The server generates the
   covering chunks lazily, lit by the same `mc_world::light` BFS
   engine that drives the rest of the chunk stream.
4. Breaks/places blocks anywhere. Edits in *generated* chunks
   land in the same dirty-flush pipeline M6 built. After a
   restart, the generated terrain *plus* the edits are visible
   on disk — the generator never runs twice for the same chunk.

The acceptance gate is a manual run + an integration test that
boots the server against a temp dir (no `region/` at all) and
asserts a far chunk position resolves to a `Chunk` with non-air
blocks at the expected height range.

## Strategy

- **No vanilla algorithm.** Per ADR 0001 + the source-level
  prohibition in PROJECT_SPEC §8.1, Solaris doesn't translate
  vanilla's RNG / climate noise / cave carver / structure
  placer. M7 ships an *independent* terrain generator: a
  Perlin-style hash-based 2D noise with a configurable seed,
  producing a smooth height field. Vanilla parity is *explicitly
  out of scope*; the bar is "playable", not "identical".
- **Single biome.** Every cell is `minecraft:plains`. Biome
  selection, climate noise, biome blends — all M9+.
- **Three-layer column.** From bottom to top:
  - `y = MIN_Y` → `minecraft:bedrock`.
  - `MIN_Y < y < height - 3` → `minecraft:stone`.
  - `height - 3 ≤ y < height` → `minecraft:dirt`.
  - `y == height` → `minecraft:grass_block`.
  - `y > height` → `minecraft:air`.
  No water (sea level handling is M9+; the M7 generator's height
  field is centred above sea level so the player walks on land).
- **Heightmaps.** `MOTION_BLOCKING` + `WORLD_SURFACE` populated
  directly from the height field (one walk per column on
  generate, identical to `set_block_and_update`'s recompute).
- **`Chunk::status`** = `"full"` so the server emits the chunk
  as a fully-generated cell; vanilla's intermediate generation
  statuses are not modelled in M7.
- **Light.** The existing `mc_world::light` engine already
  handles fresh chunks (the M4 BFS runs over whatever block
  states are present). M7 doesn't pre-bake light into generated
  chunks — `section_lights` stays empty (`None` per layer) and
  the engine fills it in at emit time, same as M5 edits.
- **Persistence interaction.** Generated chunks are *dirty*
  immediately on creation, so the M6 flush pipeline writes them
  to disk on Ctrl-C. After the first flush they're identical to
  any other on-disk chunk: subsequent reads come from the
  region file, not the generator. This means the generator runs
  *once* per chunk per fresh world.
- **Seed.** A `i64` carried through `ServerConfig` →
  `WorldStorage`. Default = 0 if config doesn't supply one;
  example.toml grows a `[data].seed = 0` field with the same
  default. Re-seeding mid-world (e.g. a future `/seed` command)
  is M9+.
- **WorldStorage integration.** A new
  `Arc<dyn ChunkGenerator + Send + Sync>` field on
  `WorldStorage`. `ensure_chunk` now has three legs:
  1. cache hit → touch + return.
  2. region exists + slot has a payload → decode + insert.
  3. otherwise + generator present → generate, mark dirty,
     insert.
  4. otherwise → `None` (same posture as today).
  The order matters: a region-resident chunk *wins* over a fresh
  generation, so edits persisted from the previous session aren't
  silently overwritten by re-generation.
- **Reach.** No reach validation; the M5 trust posture stays.
- **No caves.** A surface-only terrain. Caves are M9+.

## Reference sources

- `data/vanilla/reports/blocks.json` for default-state ids of
  bedrock, stone, dirt, grass_block. Same data path as M5+.
- No vanilla bytes are read for terrain shape: M7 is fully
  algorithmic.
- The `noise` Rust crate exists; M7 *does not* depend on it —
  the 2D hash-noise we need fits in ~60 LOC and keeps the
  crate dep-free (rationale: minimising dependency surface for
  a project this early in its life).

## Sub-milestone decomposition

### M7.a — noise primitive

In `crates/mc-worldgen/src/noise.rs`:

- `fn hash2(x: i32, z: i32, seed: i64) -> u32` — `xxhash`-style
  scrambling on `(x, z, seed)`. Bit-deterministic across runs.
- `fn value_noise_2d(x: f64, z: f64, seed: i64) -> f64` —
  smoothed bilinear interpolation between lattice values pulled
  from `hash2`. Returns `-1.0..=1.0`. Smooth, deterministic, no
  external crate.
- Unit tests: determinism across calls, range bound, that two
  seeds produce different outputs at the same coords.

### M7.b — `TerrainGenerator`

In `crates/mc-worldgen/src/terrain.rs`:

- `pub trait ChunkGenerator: Send + Sync` exposing
  `fn generate(&self, pos: ChunkPos) -> Chunk`.
- `pub struct TerrainGenerator { seed: i64, registry:
  Arc<BlockRegistry>, /* resolved state ids */ }`.
- `fn new(seed, registry) -> Self` resolves
  `air / bedrock / stone / dirt / grass_block` once.
- `generate` walks each `(x, z)` column, samples a height via
  the noise primitive (`height ≈ 64 + 12 * noise(x/24, z/24)`
  rounded), fills the column per the three-layer rule, sets
  `MOTION_BLOCKING` and `WORLD_SURFACE` heightmaps, status =
  `"full"`. Mark `dirty = true` so the M6 flush picks it up.
- Unit tests: generate `(0, 0)`, assert
  `get_block(8, height_at_origin, 8)` = grass_block + bedrock
  at MIN_Y. Same seed produces the same chunk twice.

### M7.c — `WorldStorage` falls back to generator

In `crates/mc-world/src/storage.rs`:

- `WorldStorage` grows
  `generator: Option<Arc<dyn ChunkGenerator + Send + Sync>>`.
- `WorldStorage::with_generator(self, gen) -> Self` builder.
- `ensure_chunk` reorders to: cache → region → generator →
  None. Generator-produced chunks are inserted as dirty.
- Unit test: open an empty tempdir world *without* any region
  files, with a generator attached, `get_block` at far
  coordinates resolves to non-air at the expected height.

### M7.d — config + `mc-server` wiring

In `crates/mc-server/src/lib.rs` and `main.rs`:

- `DataSection` grows `#[serde(default)] seed: i64`.
- `example.toml` adds `seed = 0` with a comment.
- `main.rs` constructs a `TerrainGenerator` from the seed +
  block registry and passes it through
  `WorldStorage::with_generator` before wrapping in the
  `Arc<Mutex<>>`.
- `mc_net::ServerConfig` stays untouched — the generator hides
  behind the world handle.

### M7.e — integration test

`mc-test-harness/tests/worldgen.rs`:

- Boots `mc_net::run` against a `tempdir` with no region files
  + a `TerrainGenerator(seed=42)`. Walks login + configuration
  + draws the spawn burst, asserts the burst delivers
  `≥ 441 chunks` (the full view-distance window) without any
  "absent" frames.
- Picks a chunk far from origin (`(50, 50)`) and asserts via
  the shared world handle (post-burst) that the cell at
  `(50*16+8, 75, 50*16+8)` is either stone, dirt, grass_block,
  or air (depending on the generated height) — i.e. *not* the
  empty-chunk default.
- Optional: place a block at a generated chunk, flush, reopen,
  reread — same flow as the M6.g harness, but on a chunk that
  never existed on disk at session start.

## Acceptance criteria

1. `cargo test --workspace` green (M6 + M7 additions).
2. `cargo clippy --workspace --all-targets -- -D warnings` clean.
   `cargo fmt --all -- --check` clean. No `unsafe`.
3. `TerrainGenerator::generate` is deterministic for a given
   `(seed, pos)`; pinned in unit tests.
4. `WorldStorage` with a generator attached resolves *every*
   chunk position to a non-empty `Chunk`; pinned in unit + integ
   tests.
5. Edits in generated chunks survive a `flush_dirty` + reopen
   round-trip (same gate as M6.g, retargeted).
6. A vanilla 26.1.2 client connecting to an empty-world + generator
   server sees solid ground in every direction.
7. No vanilla algorithm in the repo. The terrain function is
   ours.

## Out of scope (so it does not creep)

- Biomes (single plains).
- Structures (trees, villages, dungeons, mineshafts).
- Caves / 3D noise.
- Ores.
- Water / sea-level handling beyond "terrain is centred above 63".
- Vanilla parity. Two players running the same seed on Solaris vs
  vanilla will see *different* terrain. M7's seed only fixes
  Solaris-vs-Solaris reproducibility.
- Performance tuning. M7 generates one chunk at a time; a 441-chunk
  spawn burst on a fresh world will be slow on first connect.
  Async / parallel generation is M9+.
- Per-chunk generation status (`"biomes"`, `"structures_starts"`,
  …). All M7 chunks ship `"full"`.

## Open questions

- **Lighting on first generation.** The generator leaves
  `section_lights` empty, the engine fills it at emit time
  (~150 ms per chunk in debug). On a fresh spawn burst this
  pushes the first-connect time well past M4.f's baseline.
  Acceptable for an MVP, M9+ may want pre-baked light from the
  generator.
- **Generator state across forks.** `WorldStorage::flush_dirty`
  drops the in-memory chunk after eviction, but a re-fetch goes
  to disk first (now that the chunk's been persisted). For a
  *non-flushed* chunk that's evicted, the generator re-runs and
  produces an identical-by-seed result. As long as the player
  hasn't touched it, this is safe; once they edit, the
  eviction-flush in M6 protects them.

## Pitfalls

- **Heightmap units.** Heightmaps store `height - MIN_Y + 1`,
  not raw `height`. Off-by-one here pretty much guarantees
  weird visuals (light leaks, mob spawn glitches).
- **MIN_SECTION_Y offset.** Sections are indexed `0..=23`
  mapping to `y / 16 + 4`. The bedrock layer at `MIN_Y = -64`
  lives in section index 0.
- **Default biome.** `Chunk::empty` already takes a default
  biome; pass plains explicitly. Every biome section stays
  `BiomeSection::Single(plains)` after generation.
- **Section palette singletons.** A column with only stone
  produces a `BlockStorage::Single(stone)` section, no `data`
  long-array on disk. Make sure the encoder handles the
  singleton path (M2 already does).
- **Don't write generator output to `data/` or `.analysis/`.**
  Generated chunks live in the world's own region directory.
  Per [[feedback-no-external-artifacts]], no Mojang bytes
  involved here, but the gitignore for region files is the
  operator's responsibility (their world dir, their gitignore).

  `worldgen.rs` integration test).

## Open follow-ups (handed to M8+)

- **Biomes.** Single-plains forever. Biome selection / climate
  noise / blending lands with the wider mc-data registry work.
- **Caves / 3D noise / ores.** All surface-only in M7.
- **Structures.** No trees, villages, dungeons, mineshafts.
- **Water / sea level.** Terrain centred above sea, no water
  generated. Fluids land with spec-M5 (block physics).
- **Vanilla parity.** Explicit non-goal. Solaris seeds are
  Solaris-only.
- **Async / parallel generation.** First-connect spawn burst on
  a fresh world generates ~441 chunks serially in the storage
  mutex — acceptable for MVP, slow in practice. M9+ perf work.
- **Pre-baked lighting on generation.** Light engine runs at
  emit time, adding ~150 ms/chunk in debug to the first-spawn
  burst on a fresh world.
- **Multi-seed support / `/seed` command.** Seed is one
  per-config value, fixed for the run.
