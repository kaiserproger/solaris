# M88 - Persistence And Crash Recovery Hardening

**Status:** Planned. Quality label: `stabilization`.

## Agent Start Prompt

Read M77-M87, M27-M29, M42, M48-M49, and persistence/storage code. Run
preflight. Make save/restart/crash behavior credible.

## Goal

Prevent ordinary data loss/corruption for scoped MVP gameplay state.

## Scope

- Durable writes: unique same-directory temp file, file fsync, and
  parent-dir fsync where supported. Existing-file region replacement is
  guarded by an on-disk file-version check; Windows existing-file
  replacement is reported as unsupported until an atomic replace path is
  implemented. Parent-dir fsync `Unsupported`, plus Windows directory
  `PermissionDenied`, is treated as unavailable durability rather than
  a proved sync. Stale temp cleanup is limited to the writer-owned temp
  file because deleting fixed names can race other writers.
- Multi-file save consistency for players, world metadata, entities,
  chunks, block entities, scheduled ticks, containers, vehicles, weather,
  and time.
- Playerdata: gamemode, abilities, selected slot, inventory/armor,
  health/food, spawn/death state, cursor/open-container recovery.
- Campfire in-flight slots, furnace/cooking runtime, sign NBT, barrel
  identity/storage, plant states, drops, and scheduled/random tick state.
- Anvil compression ids including LZ4; `.mca` light arrays; level.dat
  spawn/seed/generator/time/weather policy.
- Solaris sidecar format inventory/versioning, backup/restore dry-run,
  migration stance.

## Acceptance

- Save/restart scenario covers players, chunks, block entities,
  containers, entities/drops, weather/time.
- Fault injection covers partial writes, interrupted save-all, and
  corrupted sidecar/chunk recovery.
- Operator docs explain backups and recovery limits.
