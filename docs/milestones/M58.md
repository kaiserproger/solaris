# M58 - Crop harvest drops

**Status:** In progress. Branch: `dev/M58-crop-harvest-drops`.
**Owning crates:** `mc-net` for block-break drop selection and item-entity
spawning, `mc-data` only if the explicit crop drop helper belongs beside loot
data, `mc-test-harness` for survival coverage, `docs` for readiness updates at
closeout.

## Goal

Make basic farming self-sustaining in normal survival play: mature crops broken
by a player should produce useful harvest items instead of behaving like generic
block drops.

This follows directly from M57 crop growth and bonemeal. It closes the next
visible farming gap with existing block-break, item-drop, inventory, and harness
paths, and it avoids protocol guessing entirely.

## Scope

- Add deterministic Solaris crop harvest drops for the common age-based crops
  already supported by M57 growth: wheat, carrots, potatoes, beetroots, and
  nether wart.
- Start with a small M58.a vertical slice for wheat only.
- Route crop harvest through the existing survival block-break path and item
  entity spawning path.
- Resolve item ids through the loaded item registry by namespaced id; do not
  hardcode numeric item ids.
- Use block state properties from the loaded block registry to distinguish
  mature and immature crops.
- Allow more than one stack to drop from a broken crop where needed.
- Keep the rules deterministic and documented instead of claiming vanilla loot
  table, fortune, or RNG parity.
- Add focused unit tests first, then a Solaris-only harness test once the wheat
  slice is stable.

## Non-Goals

- Full vanilla loot-table execution.
- Fortune, Silk Touch, shears, explosion decay, tool predicates, or luck/RNG
  parity.
- Automatic replanting, villager farming, composter behavior, bees, farmland
  hydration changes, or crop trampling changes.
- Sound, particle, game-event, statistic, advancement, or recipe-book updates.
- New packet IDs, field layouts, block/entity metadata, or guessed clientbound
  effects.
- Tree/sapling growth, stem crops, sweet berry bushes, cocoa, cactus, sugar cane,
  bamboo, kelp, chorus plants, or mushrooms.

## Strategy

1. Keep M58.a entirely on verified gameplay paths: existing player block break,
   block updates/acks, item entity spawn, pickup, and item registry lookup.
2. Replace the one-stack `block_drop_stack` call site with a small multi-drop
   path, preserving generic block behavior as a single-stack fallback.
3. Add an explicit crop-drop helper that takes the previous block state and
   returns zero or more item stacks for supported crops.
4. For M58.a, support only `minecraft:wheat`:
   - age 7 drops `minecraft:wheat` x1 and `minecraft:wheat_seeds` x1;
   - ages 0-6 drop `minecraft:wheat_seeds` x1;
   - if either item is absent from the item registry, omit only that missing
     stack and do not panic.
5. Use the block state's `age` property and registry block id, not numeric block
   state ids.
6. Spawn each resulting stack through the existing item entity path at the broken
   block center, then run the existing nearby-pickup pass once after spawning.
7. Defer broader crop families until the wheat helper and multi-drop seam are
   covered by focused tests.
8. Update `docs/REPLACEMENT_READINESS.md` only at closeout with the exact crop
   harvest claim that landed.

## Protocol and Data Oracles

- M58.a must not add new packet IDs or field layouts. It should reuse existing
  verified block break, block update/ack, item entity spawn, pickup, inventory,
  and registry paths.
- No `wire-probe` or `javap` oracle is required for M58.a if sounds, particles,
  statistics, game events, metadata, and new clientbound effects remain deferred.
- Vanilla data sidecar is required for block and item registries. Crop maturity
  must be read from namespaced block id plus the `age` property, not from numeric
  block state ids.
- Crop drop quantities in M58 are Solaris-owned deterministic rules, not a
  translation of Mojang loot-table algorithms.
- If a later slice attempts exact vanilla loot-table execution, fortune/RNG extra
  yields, poisonous potato chance, particles, sounds, statistics, or game events,
  first capture or cite the needed behavior from the local oracle per ADR 0002 and
  keep Mojang data files as runtime input per ADR 0001.

## Risks

- The current generic block-drop path returns at most one stack. M58.a should keep
  the multi-drop seam narrow and prove generic block drops are unchanged.
- Vanilla crop loot tables contain conditions/functions that the current simple
  loot loader intentionally skips. Do not widen the loader into partial generic
  loot execution for M58.a.
- Item entity drop observation in the harness can race pickup. Prefer an existing
  deterministic pickup/inventory observation if available, or wait on existing
  visibility events rather than sleeping.
- Missing item ids from a minimal test registry should not panic. Unit tests need
  a missing-item case.
- Deterministic minimum yields are intentionally less generous than vanilla.
  Document this as partial farming support instead of parity.
