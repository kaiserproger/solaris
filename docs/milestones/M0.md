# M0 — Project Bootstrap

**Status:** complete (pending owner review and `m0` tag).

## Scope

Scaffold the Cargo workspace, CI, base crates and a `mc-server` CLI stub that
parses a TOML config. No game logic. The authoritative specification of M0 is
[`../CLAUDE_CODE_PROMPTS.md`](../CLAUDE_CODE_PROMPTS.md) §3.

## Acceptance criteria (status)

1. `cargo build --release` succeeds — verify locally with the command in the
   [README](../../README.md).
2. `cargo test --workspace` passes, ≥ 1 test per crate (12 placeholder
   `it_compiles` tests + `mc-server` lib test + 3 CLI integration tests).
3. `cargo fmt --check` exits 0.
4. `cargo clippy --workspace --all-targets -- -D warnings` exits 0.
5. `cargo run --bin mc-server -- --config example.toml` reads the config and
   prints it as pretty JSON.
6. CI workflow in `.github/workflows/ci.yml` runs fmt / clippy / test / build.
7. Each crate's `Cargo.toml` has `description`, inherits `version = "0.0.1"`
   and shared workspace metadata.
8. `unsafe_code = "forbid"` is set at the workspace lints level.
9. No Minecraft-specific dependencies: only `tokio`, `serde`, `serde_json`,
   `toml`, `tracing`, `tracing-subscriber`, `clap`, `anyhow`, `thiserror`
   (declared at workspace level; only the subset actually needed by
   `mc-server` is pulled in).

## Deviations from the prompt

- Codename chosen as **Solaris** (from the working directory name). Per
  PROJECT_SPEC §0 this fixes the protocol-extension namespace prefix to
  `solaris:…` rather than the placeholder `mcengine:…` used in §5.2 — the spec
  needs an update in a later pass.
- `predicates` is added as a dev-dependency of `mc-server` alongside
  `assert_cmd` and `tempfile`: it is the canonical assertion helper for
  `assert_cmd` and using it keeps integration assertions readable. It is test
  infrastructure, not a runtime dep, so it does not violate acceptance §9.
- `mc-server` exposes a small `lib.rs` (the `ServerConfig` types) so that
  integration tests and future crates can share the same types without
  re-declaring them. The binary in `main.rs` is the only place that does I/O.
- `unsafe_code = "forbid"` is enforced via workspace lints rather than ad-hoc
  in each `lib.rs` — one source of truth.
