### Generated-World Probe Follow-Up

After the initial closeout, `.analysis/test-world` was deleted and regenerated
by Solaris, not by `tools/generate-test-world.sh`. The generated artifact passed
functional validation: 4 region files, exactly 289 chunks covering `[-8..8]` in
both axes, no missing/extra chunks, zlib compression id 2, `mc-worldgen`,
`mc-world`, server spawn-window, harness worldgen/chunk-stream/persistence, and
post-probe real-test-world checks all passed. A long `wire-probe` against the
debug server saw all 289 unique `LevelChunkWithLight` packets with no
duplicates.

The same probe exposed readiness-blocking performance debt. Server metrics for
the view-distance-8 window included `elapsed_ms=17326`, `first_chunk_ms=177`,
`ring1_complete_ms=793`, `ring2_complete_ms=1652`, `fetch_ms=27771`,
`light_compute_ms=50489`, repeated runtime tick warnings around 150-377 ms,
`chunk_prepare` lock waits up to hundreds of ms, and `save-all` dirty flush
pressure after runtime ticks. This is now a required M90/M91 fix target, not a
release-ready datapoint.
