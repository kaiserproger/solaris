# M38 - Vanilla replacement readiness polish

**Status:** implemented locally on `dev/M37-performance-scale` from local M37
head `9635087` (`feat: M37 performance and scale`). The expected reviewed
`m37` tag was not present locally when this work started.
**Owning crates:** `mc-net` for play-state compatibility and packet recovery,
`mc-protocol` for malformed packet coverage, and `docs` for operator/readiness
notes.

## Goal

Run down the remaining vanilla-client incompatibilities and common survival
paper cuts before describing Solaris as a scoped overworld-survival replacement.

M38 does not claim bit-perfect parity, other dimensions, redstone completeness,
villager/trading systems, or broad vehicle/projectile simulation. Those remain
explicitly outside this readiness pass unless a manual gate proves they block the
scoped replacement claim.

## Current Foundation

- M24-M37 added data-driven survival systems, containers, recipes, mobs/combat,
  multiplayer hardening, and performance budgets.
- M37 closeout left protocol-visible polish and M39 lock mitigation as remaining
  risks.
- Local dirty files (`example.toml`, `tools/*`, `.serena/`, `YOLO_MODE.md`,
  `log.log`, `opencode.json`) pre-existed this slice and are not M38 scope.

## Strategy

1. Create an explicit readiness checklist instead of implying replacement parity.
2. Prepare an owner-run PrismLauncher 26.1.2 manual gate.
3. Fix high-value, surgical paper cuts in already-shipped interaction paths.
4. Add protocol negative tests for common client misbehavior.
5. Update operator docs with sidecar and debug-server run instructions.
6. Close out with clear supported/deferred claims.

## Readiness Checklist

Supported in the scoped claim:

- Vanilla 26.1.2 login/config/play handshake.
- Overworld chunk streaming, lighting, block edits, persistence, basic survival
  mining/placing, fluids, farming, crafting, furnace/chest/barrel-style storage,
  mobs/combat, death/respawn, commands/admin basics, save/restart, and multiple
  clients within current load budgets.

Partially supported and covered by M38 polish:

- Beds set the persisted respawn anchor, but sleeping/time-skip is not claimed.
- Signs place as blocks, but editable sign text is deferred until the
  serverbound sign update packet is verified from local vanilla oracles.
- Smoker/blast furnace interactions use furnace storage/cooking behavior and do
  not claim recipe-speed differences yet.
- Barrels use chest-style storage semantics without block-animation parity.

Deferred beyond M38:

- Other dimensions, portals, boats/minecarts, bows/arrows, shields, redstone
  parity, villagers/trading, structures, weather, full recipe book parity, and
  M39 lock-free hardening.

## Manual Gate Script

Owner-run gate:

```sh
cargo run --bin mc-server -- --config example.toml
```

Then connect a vanilla 26.1.2 PrismLauncher client and run:

1. New world join, chunk load, move around spawn.
2. Disconnect/reconnect and verify position/inventory persistence.
3. Explore far enough to stream new chunks and watch server metrics.
4. Mine/place common blocks, doors, trapdoors, water/lava buckets, signs, and a
   bed.
5. Use crafting table, chest, barrel, furnace, smoker, and blast furnace.
6. Farm wheat on farmland, trample farmland, and verify random growth still runs.
7. Fight hostile mobs, collect drops/XP, die, respawn, and act again.
8. Save/restart the server and verify blocks, containers, playerdata, XP, and bed
   respawn point survive.
9. Connect a second client and verify player visibility, shared pickups,
   containers, block edits, and reconnect behavior.

Known manual checks not claimed green until owner reports them:

- Client sign text editing.
- Bow/projectile combat.
- Shield blocking.
- Boat/minecart riding.
