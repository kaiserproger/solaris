# M81 - Automation Blocks And Redstone-Lite

**Status:** Planned. Quality label: `draft`.

## Agent Start Prompt

Read M77-M80, container/furnace/campfire/barrel closeouts, and the
validation ledger. Run preflight. Implement only automation rows marked
as M100 blockers.

## Goal

Add survival-useful automation without attempting full redstone parity.

## Scope

- Decide support for hoppers, comparators, buttons, levers, pressure
  plates, powered doors/trapdoors, and simple power propagation.
- Cover hopper/comparator behavior for campfires, furnace-family blocks,
  barrels/chests, and supported containers.
- Explicitly defer complex redstone update order, pistons, observers,
  quasi-connectivity, and contraptions unless owner changes scope.

## Acceptance

- Supported automation has focused runtime tests.
- Client-visible automation has oracle or real-client evidence.
- Deferred redstone is listed as accepted non-goal or M101+ debt.
- No global tick or lock regression from automation scans.

## MVP Decision

Quality label: `draft`.

This pass chooses a docs-only automation/redstone-lite decision instead of
landing a fake public abstraction. The earlier comparator fullness helper had
no runtime call path, so it was removed rather than treated as shipped support.
Solaris does not expose comparator readout, scan the world, schedule ticks, or
update neighboring blocks in this slice.

Supported in this slice:

- No runtime automation code landed.
- Comparator readout remains debt until it has a real runtime call path,
  max-stack metadata integration, and validation beyond helper-only tests.

Deferred beyond this slice:

- Hopper insertion/extraction and transfer scheduling.
- Comparator block placement, neighbor updates, wire propagation, and
  client-visible redstone state changes.
- Buttons, levers, pressure plates, powered doors/trapdoors, pistons,
  observers, quasi-connectivity, and exact vanilla update order.
- Campfire comparator/hopper behavior, because the current runtime campfire
  state is not represented as a comparable inventory block entity.

No helper-only tests remain because tests should exercise shipped behavior, not
unused draft helpers. This docs-only decision is not counted as vanilla/client
evidence and does not claim redstone, automation, or comparator parity.
