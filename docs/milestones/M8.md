## Goal

After M8 a vanilla 26.1.2 client connecting to Solaris sees:

1. **Spawn burst starts at the player's chunk.** Visually:
   the spawn tile renders first, then concentric rings outward.
   Less perceptual lag at the centre, same total work.

## Strategy

- **Spiral iteration.** Replace the row-major two-loop in
  `emit_chunks_around` with a square-spiral that walks
  `(0,0), (1,0), (1,1), (0,1), (-1,1), …` until the full
  `(2*vd+1)² ring` is covered. Same chunks, different order.
  No new state; runs in `O(R²)` like the current code.

## Sub-milestone decomposition

### M8.a — Set Compression at login (deferred)

The codec already supports `Compression::Threshold(n)` but
emitting `SetCompression` from the login handler is intrusive: the
server-side currently threads `Compression::Disabled` through
every handler and every test (raw-TCP `mc-server/tests/*.rs`
parse frames with hard-coded `Compression::Disabled`). Wiring
this in safely needs a session where the manual gate can confirm
the boundary works against the real vanilla client. Deferred to
M9+.

### M8.b — Spiral chunk iteration

In `crates/mc-net/src/play.rs` (the iterator now lives in
`crates/mc-net/src/play/chunk_stream.rs`): replace the
`for cz … for cx …` row-major emission with a
`spiral_chunks(center, view_distance)` iterator. Unit-test the
iterator's coverage + ordering invariants.

### M8.c — closeout

Update this doc + README + memory. Merge to main + tag `m8`.

## Out of scope

- **Incremental relight.** The most-wanted perf item; lives on
  the M9+ backlog because a diff-based light BFS is its own
  milestone-scale piece of work.
- **LZ4 chunk read path.** M3 carry-over. Adds a 5th
  compression-type branch in the Anvil reader; needs lz4 crate
  + a real LZ4-compressed chunk to test against. M9+.
- **`SetDefaultSpawnPosition` re-introduction.** The 26.1.2
  wire shape is uncertain (the existing code comments out the
  packet, citing layout drift). Needs wire-probe verification
  against a real vanilla server — not safe to do autonomously.
- **Async / background flush.** Same as M6 / M7 follow-ups.
- **Pre-baked lighting on generation.** Same as M7 follow-ups.

## Pitfalls

- **Compression threshold flip.** Both sides have to switch the
  codec on the *same* packet boundary. Vanilla orders it:
  CB `SetCompression` (uncompressed frame), then CB `LoginSuccess`
  (first compressed frame). Off-by-one here would desync the
  framing and the client disconnects with garbled bytes.
- **Spiral termination.** The spiral generator must produce
  exactly `(2*vd + 1)²` cells. Easy to off-by-one and leave a
  corner unfilled.
