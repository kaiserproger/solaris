# M45 - Manual physics feel gate

**Status:** draft plan for owner review. Proposed branch:
`dev/M45-manual-physics-feel`, cut from `main` at tag `m44` after M44 is merged.
**Owning crates:** `mc-test-harness` for any new observable checks, `mc-net` for
play-state movement and packet behavior, `mc-physics` only if a vanilla-backed
movement primitive must change.

## Goal

Turn the remaining M40/M41 owner-facing physics symptoms into a repeatable manual
gate and fix only the pieces that can be tied to a vanilla or runtime-state
oracle.

## Scope

- Player swimming feel and pose transitions in shallow/deep water.
- Server/client correction behavior during sprint-swim, surfacing, and leaving
  water.
- Manual PrismLauncher 26.1.2 notes captured as a stable checklist.
- Optional runtime-side assertions for player water state if they make the manual
  symptom testable.

## Non-Goals

- Bit-perfect vanilla movement constants.
- Boats, vehicles, projectiles, bubble columns, or broad aquatic gameplay.
- Collision/fall/fluid parity unrelated to the manual water-feel gate.

## Strategy

1. Start with the M44 water captures and owner manual report.
2. Add a checklist that distinguishes visual feel, wire corrections, and server
   pose/state.
3. Capture any missing vanilla signal before changing movement behavior.
4. Prefer one minimal runtime fix at a time, with a harness assertion or explicit
   manual-gate note.

## Sub-Milestones

### M45.a - Manual Gate Definition

Acceptance:

- Document the exact PrismLauncher 26.1.2 route and expected observations.
- Split observations into `passes`, `fails`, and `needs capture`.
- Record which parts are wire-visible and which are visual/manual only.

### M45.b - Player Water State Assertions

Acceptance:

- Add focused runtime assertions only if they observe real play-path state.
- Keep M44 water `wire-probe` scripts green and documented.
- Do not change player movement constants without a vanilla-backed reason.

### M45.c - Minimal Player Feel Fixes

Acceptance:

- Any gameplay fix cites a vanilla capture, runtime-state assertion, or owner
  manual gate failure.
- Existing player presence, reach, block edit, and mob tests remain green.
- Deferred non-player aquatic polish stays out of scope.

### M45.d - Closeout

Acceptance:

- Record manual gate status, validation, and remaining symptoms.
- If visual feel still needs engine-level work, route it to a later milestone
  with the missing oracle listed.

## Validation

```sh
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Focused gates:

```sh
cargo test -p mc-test-harness --test physics_validation -- --nocapture
cargo test -p mc-test-harness --test player_presence -- --nocapture
cargo test -p mc-test-harness --test block_edit -- --nocapture
```

Manual gate:

```sh
RUST_LOG=mc_server=info,mc_net::server=debug,mc_net::lock_metrics=warn \
  cargo run --bin mc-server -- --config example.toml
```

## Risks

- Player movement fixes can make client prediction worse while tests still pass.
- Manual-only symptoms are easy to overfit; require a clear checklist entry before
  changing code.
- Water behavior shares code with reach, sprinting, and pose metadata.
