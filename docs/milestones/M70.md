# M70 - Client-visible metadata and sign editing

**Status:** In progress locally; M70.a packet/open-editor slice landed. Branch:
`dev/M70-visible-metadata`, stacked after local M69.
**Owning crates:** `mc-protocol`, `mc-net`, and targeted world/storage support if
sign block-entity text needs persistence.

## Goal

Close the highest-visibility metadata gaps from the readiness review without
guessing packet layouts: sign editing, sign block-entity updates, campfire visual
state, and shield pose/entity metadata.

## Priority Backlog

### M70.a - Sign Editor Packets And Server Flow

Implement the minimum oracle-backed sign editing path.

Oracle evidence:

- `.analysis/protocol-dump.txt` records `ClientboundOpenSignEditorPacket` fields:
  `BlockPos pos`, `boolean isFrontText`.
- `.analysis/protocol-dump.txt` records `ServerboundSignUpdatePacket` fields:
  `BlockPos pos`, `String[] lines`, `boolean isFrontText`.
- `.analysis/protocol-dump.txt` records `ClientboundBlockEntityDataPacket` fields:
  `BlockPos pos`, `BlockEntityType<?> type`, `CompoundTag tag`.
- Local vanilla 26.1.2 bytecode/probe under
  `/tmp/opencode/solaris-m70-oracle` verified `SignBlockEntity.saveAdditional`
  writes `front_text`, `back_text`, and `is_waxed`; `SignText.DIRECT_CODEC`
  writes `messages`, optional `filtered_messages`, `color`, and
  `has_glowing_text`; a plain literal component encodes to an NBT string.
- `data/vanilla/reports/registries.json` records block-entity type protocol id
  `minecraft:sign` = `7`.

Scope:

- Add packet codecs and layout tests for open-sign editor and sign update.
- After sign placement, send the open-sign-editor packet for the placed sign.
- Accept sign update packets only for a valid placed sign position.
- Store and broadcast/display sign text via block-entity data if the required NBT
  shape can be verified from local vanilla output.

Non-goals:

- Hanging-sign parity unless it falls out for free from the same verified packet
  path.
- Styled/signed chat text parity beyond plain line text accepted by vanilla.
- Guessing sign block-entity NBT.

Landed so far:

- Added packet codecs and protocol-dump-backed tests for
  `ClientboundBlockEntityData`, `ClientboundOpenSignEditor`, and
  `ServerboundSignUpdate`.
- Open the vanilla sign editor after successful normal sign placement.
- Decode sign update packets and accept them only when they match the currently
  opened placed-sign position and the block is still an editable sign.
- Accepted sign updates now store opaque sign block-entity NBT and emit
  `ClientboundBlockEntityData` with vanilla-shaped plain-text sign NBT to the
  editor and other sessions that have the chunk loaded.

### M70.b - Campfire Block-Entity Visual Metadata

Make campfire cooking client-visible when an item is cooking.

Oracle evidence:

- Local vanilla 26.1.2 bytecode under `/tmp/opencode/solaris-m70-oracle`
  verified `CampfireBlockEntity.getUpdateTag` calls `ContainerHelper.saveAllItems`
  only. Full save also writes `CookingTimes` and `CookingTotalTimes`, but those
  are not part of the client update tag.
- `data/vanilla/reports/registries.json` records block-entity type protocol id
  `minecraft:campfire` = `33`.

Scope:

- Use oracle-backed `ClientboundBlockEntityDataPacket` layout.
- Verify the campfire block-entity NBT shape from local vanilla before encoding it.
- Emit updates when a cooking item is inserted, completes, or the campfire is
  broken/replaced.

Non-goals:

- Hopper/comparator automation.
- Smoke/sound particle parity unless packet evidence is captured separately.
- Restart persistence for in-flight cooking unless block-entity storage is already
  needed for the visual state.

Landed so far:

- Runtime campfire cooking now tracks the input item separately from the output
  drop, and emits a vanilla-shaped `Items` block-entity update on insert and
  completion.
- Replacing/breaking a campfire clears the runtime cooking state and broadcasts
  an empty `Items` update to loaded sessions.

### M70.c - Shield Pose Metadata

Make shield use visible to other clients where vanilla uses entity metadata.

Oracle evidence:

- Local vanilla 26.1.2 probe under `/tmp/opencode/solaris-m70-oracle`
  verified `EntityDataSerializers.BYTE` serializer id `0` and
  `LivingEntity.DATA_LIVING_ENTITY_FLAGS` metadata index `8`.
- Local `javap` of `LivingEntity` verified `startUsingItem` sets flag bit `1`
  for using an item and flag bit `2` when the used hand is offhand; `stopUsingItem`
  clears bit `1`.

Scope:

- Reuse existing `ClientboundSetEntityData` only with metadata indexes and
  serializer ids verified from local vanilla/decompiled sources.
- Broadcast start/stop metadata transitions when shield use starts or is cleared.
- Keep the existing runtime blocking rules unchanged.

Non-goals:

- Durability, axe disable, exact vanilla angle/timing, sounds, or particles.

Landed so far:

- Shield start/clear now broadcasts `ClientboundSetEntityData` transitions for
  the vanilla living-entity using-item byte while leaving Solaris blocking rules
  unchanged.
