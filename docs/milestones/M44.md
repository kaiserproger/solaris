# M44 - Physics parity fixes

**Status:** plan on `main` from local M41 recovery head `8b85e97`
(`feat: M39-M41 manual recovery hardening`). M44 must consume the M43 mismatch
report; it should not start by guessing fixes.
**Owning crates:** `mc-physics` for movement/collision primitives, `mc-net` for
play-state behavior and packet dispatch, `mc-world` for block/fluid/scheduled tick
state, `mc-entity` for AI goals, and `mc-test-harness` for regression coverage.

## Goal

Fix the highest-priority vanilla physics mismatches proven by M43, with tests that
exercise the same real play/runtime paths that failed manually.

M44 is the implementation counterpart to M43. Every non-trivial fix must cite the
M43 oracle or manual capture that proves the mismatch.

## Current Foundation

- M40/M41 added partial water/drop/mob recovery work but explicitly did not close
  the manual gameplay gaps.
- M43 is expected to provide a ranked mismatch backlog before M44 code changes.
- Existing systems are intentionally scoped: Solaris is not trying to be bit-perfect
  vanilla redstone/vehicle/projectile parity in this milestone.

## Strategy

1. Fix only cases reproduced or captured in M43.
2. Land fixes in small slices with one behavior class per commit where practical.
3. Keep vanilla-oracle citations in tests or milestone notes, not in speculative
   comments.
4. Preserve replacement-server behavior already covered by M38-M41.
5. Prefer server-authoritative correctness over client-side visual hacks; use
   visual assists only when vanilla behavior is client-predicted and documented.

## Sub-Milestones

### M44.a - M43 backlog triage

Convert the M43 mismatch report into a fix order.

Acceptance:

- Each selected fix has severity, reproduction, oracle citation, impacted crates,
  and expected regression tests.
- Deferred mismatches are explicitly listed with why they are out of M44 scope.
- No gameplay code changes land before this triage is written.

### M44.b - Player water and swimming fixes

Fix the player water behavior proven wrong by M43.

Acceptance:

- Entering water, swimming horizontally, swimming up/down, surfacing, and leaving
  water match the M43 oracle within documented tolerance.
- The fix handles serverbound input/commands, pose metadata, motion/correction, and
  fall damage/trample side effects as required by the oracle.
- A vanilla client can manually swim in PrismLauncher 26.1.2 without bottom-walking
  as the only available movement.
- Existing movement, reach, mining, and multiplayer visibility tests still pass.

### M44.c - Drop visibility and pickup fixes

Fix item-drop behavior proven wrong by M43.

Acceptance:

- Survival block drops are visible before pickup and collect promptly.
- Creative/no-loot cases do not spawn drops.
- Mob drops and death drops keep correct spawn/data/take/remove/inventory ordering.
- Pickup delay is stored and advanced in a way that survives normal tick timing and
  does not require ad-hoc side effects at each spawn site.

### M44.d - Sugar cane and block support fixes

Fix support/break behavior for sugar cane and other M43-selected block support
cases.

Acceptance:

- Breaking support blocks updates dependent blocks and drops according to the M43
  vanilla oracle.
- Scheduled updates do not disappear when chunks unload/reload.
- Fluid adjacency/support rules use data-derived block facts where possible.
- Block edit and persistence harnesses cover the real play path.

### M44.e - Aquatic and land-mob water movement fixes

Fix mob movement cases proven wrong by M43.

Acceptance:

- Fish/squid-like entities move through water with sane vertical and horizontal
  motion and orientation.
- Land mobs in water float/swim/escape according to the scoped oracle behavior.
- Entity motion packets, relative moves, rotations, and visibility updates remain
  bounded and per-viewer correct.
- Existing combat and mob-drop tests remain green.

### M44.f - Collision and fall-damage fixes

Fix selected collision/fall-damage mismatches from M43.

Acceptance:

- Flat ground, wall collision, selected step-up behavior, water-entry fall damage,
  and landing fall damage match M43 expectations.
- Player and entity AABB changes do not break reach validation or mob melee tests.
- Any remaining mismatch is explicitly deferred.

### M44.g - Fluid interaction fixes

Fix selected water/lava/fluid-flow mismatches from M43.

Acceptance:

- Source/flowing states, bucket replacement, underwater breaking, water/lava solid
  formation, and scheduled fluid ticks match the selected oracle cases.
- Existing fluid persistence and scheduled tick tests remain green.
- Work remains bounded by simulation budgets.

### M44.h - Integrated manual replacement gate

Run the owner-facing scenario that originally failed M40/M41.

Acceptance:

- Player can swim acceptably in water.
- Broken survival blocks show visible collectible drops.
- Sugar cane support/break behavior is correct for scoped cases.
- Nearby mobs move, and fish/aquatic mobs no longer show the known sideways/bottom
  behavior from the manual report.
- TPS/lock metrics remain acceptable after M42, or any remaining pressure is
  documented as a separate performance follow-up.

### M44.i - Closeout

Record fixes, oracle citations, validation, manual-gate status, and deferred cases.

Acceptance:

- `cargo fmt --all -- --check` passes.
- `cargo test --workspace` passes.
- `cargo clippy --workspace --all-targets -- -D warnings` passes.
- Closeout maps each fixed behavior back to its M43 mismatch id.

## Validation

Baseline gates:

```sh
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Focused gates expected during implementation:

```sh
cargo test -p mc-physics --lib -- --nocapture
cargo test -p mc-net water pickup physics -- --nocapture
cargo test -p mc-test-harness --test block_edit -- --nocapture
cargo test -p mc-test-harness --test mob_presence -- --nocapture
cargo test -p mc-test-harness --test player_presence -- --nocapture
cargo test -p mc-test-harness --test persistence_inventory -- --nocapture
```

Manual gate:

```sh
RUST_LOG=mc_server=info,mc_net::server=debug,mc_net::lock_metrics=warn \
  cargo run --bin mc-server -- --config example.toml
```

Then connect PrismLauncher 26.1.2 and rerun the M40/M41 owner scenario plus every
M43 high-priority mismatch scenario.

## Risks / Pitfalls

- Fixes can accidentally chase visual symptoms instead of the server-side mismatch
  M43 identified.
- Player movement changes can fight vanilla client prediction and feel worse even
  if tests pass.
- Block support fixes can create cascading updates that break tick budgets.
- Mob movement fixes can regress combat, pickup, despawn, or visibility ordering.
- M44 must not become an unbounded physics rewrite; defer low-priority parity.
