# M48 - Chunk pipeline runtime isolation

**Status:** draft plan for owner review. Proposed branch:
`dev/M48-chunk-runtime-isolation`, cut from `main` after the preceding
milestone tag.
**Owning crates:** `mc-net` for chunk streaming and server task orchestration,
`mc-world` for disk load plans, `mc-worldgen` for generation offload,
`mc-server` for shutdown/startup behavior, and `mc-test-harness` for multicore
load coverage.

## Goal

Remove the highest-impact runtime-thread stalls and per-player oversubscription
from chunk streaming, generation, and save/shutdown paths.

M48 is a containment milestone. It should not redesign `WorldStorage`; it should
make current chunk IO, worldgen, and save work obey server-wide budgets and stay
off Tokio runtime workers.

## Scope

- Server-wide chunk IO, chunk CPU, and generation concurrency budgets.
- Off-runtime chunk disk load, NBT decode, and fresh worldgen.
- Runtime-thread isolation for persistence and dirty region writes.
- Correct Ctrl-C ordering: request shutdown before final save.
- A non-ignored multicore load smoke test proving the budgets are global.

## Non-Goals

- Sharded world storage or lock-free chunk snapshots; route to M49.
- Session visibility rewrite; route to M50.
- Protocol compression buffer rewrite; route to M51.
- Vanilla physics behavior changes.

## Current Bottlenecks

- `ChunkStreamState::new` creates per-session semaphores for chunk IO and CPU,
  multiplying configured worker counts by player count.
- `prepare_chunk_request` calls `ChunkDiskLoadPlan::load` and
  `TerrainGenerator::generate` directly in async tasks.
- Entity/world autosaves and `/save-all` run synchronous file/gzip/region writes
  from async paths.
- Ctrl-C runs `save_all` while the accept loop and gameplay tasks can still mutate
  state.

## Strategy

1. Introduce shared chunk pipeline resources owned by server state.
2. Keep per-player scheduling and send budgets, but make IO/CPU/generation permits
   process-wide.
3. Move disk load, NBT decode, generation, and save writes into `spawn_blocking`
   or a dedicated blocking worker path.
4. Preserve existing plan/write/commit splits; do not hold world locks while
   blocking work runs.
5. Add a small multicore regression gate before widening scope.

## Sub-Milestones

### M48.a - Shared Chunk Pipeline Resources

Acceptance:

- `chunk_io_threads`, `chunk_worker_threads`, and any new generation budget are
  instantiated once per bound server, not once per player.
- Every `ChunkStreamState` receives cloned handles to the shared resources.
- Runtime metrics or a focused test can prove total in-flight chunk work does not
  exceed the configured global budget under multi-client login.
- Existing chunk ordering and first-spawn behavior are unchanged.

### M48.b - Blocking Chunk Load and Worldgen Offload

Acceptance:

- `ChunkDiskLoadPlan::load` runs only in a blocking context guarded by the shared
  IO permit.
- Fresh `TerrainGenerator::generate` runs only in a blocking context guarded by a
  shared generation/CPU permit.
- Request cancellation/generation checks still discard stale results before commit.
- Chunk packet/light/frame build remains offloaded and keeps current timing
  metrics.

### M48.c - Persistence and Region Write Offload

Acceptance:

- Player, entity, world metadata, and dirty region writes do not perform blocking
  filesystem or gzip/zlib work on Tokio runtime workers.
- `save_all` still reports player/entity/metadata/flush timings separately.
- The existing dirty flush plan/write/commit lock discipline is preserved.
- Save failures remain visible in logs and `SaveAllReport`.

### M48.d - Shutdown Ordering and Task Drain

Acceptance:

- Ctrl-C first requests shutdown, then runs final save after accept/gameplay tasks
  have stopped or a bounded drain timeout has elapsed.
- The entity ticker, console task, and connection tasks observe the shutdown path
  where practical.
- A harness or unit test covers shutdown request before final save.
- Existing manual start command remains unchanged.

### M48.e - Multicore Chunk Load Gate

Acceptance:

- Add at least one non-ignored `#[tokio::test(flavor = "multi_thread",
  worker_threads = 4)]` scenario.
- The scenario connects multiple clients concurrently and forces chunk preparation
  work.
- The test asserts global worker/lock-pressure ceilings instead of only printing
  metrics.
- The ignored M37 load report can remain as a manual diagnostic, but it is no
  longer the only load signal.

### M48.f - Closeout

Acceptance:

- Document before/after behavior for runtime-thread blocking and worker budgets.
- Record any remaining blocking path with file references and route it to M49-M51.
- Baseline validation passes.

Focused gates:

```sh
cargo test -p mc-test-harness --test chunk_stream -- --nocapture

cargo test -p mc-net --lib -- --nocapture
```

## Risks

- Moving chunk load/generation into blocking workers can reorder completion; keep
  scheduler sequence checks authoritative.
- Too-small global budgets can make first spawn feel slow; expose metrics before
  tuning defaults.
- Shutdown drain must not hang forever on broken clients or blocked disk.
