# M53 - Autonomous parity gaps found and fixed

**Status:** landed locally. Branch: `dev/M53-autonomous-parity-gaps`, cut from `main` at `m52`.
**Owning crates:** `mc-test-harness` for autonomous parity scenarios, `mc-net` for gameplay/session fixes, `mc-server` for wiring, `docs` for readiness updates.

## Goal

Run the autonomous parity oracle (landed in M51) against Solaris and vanilla
to find real overworld gameplay mismatches, fix at least three concrete gaps,
and expand the parity scenario DSL to cover more observable facts (container
contents, entity spawns, projectile/arrow mechanics, drops). End with an
updated replacement readiness doc reflecting what was validated and fixed.

## Scope

- Expand `ObservationFact` to cover container contents, projectile entities,
  and timed drop events.
- Add new autonomous parity scenarios beyond the existing prelude +
  inventory fact: container open/click/close, projectile launch/land,
  entity spawn/respawn after death.
- Run scenarios against vanilla oracle; record findings in
  `.analysis/parity/` (never committed).
- Fix at least three parity gaps found by the oracle, each with a failing
  regression test before the fix.
- Update `docs/REPLACEMENT_READINESS.md` with newly validated claims and
  remaining known gaps.

## Non-Goals

- Bit-perfect vanilla parity for every mechanic.
- Redstone, villages/trading, or dimensions beyond overworld.
- Real-time autonomous fuzzer runs against CI (manual + vanilla jar required).
- Full projectile/arrow ballistic simulation (scope is parity fixes, not
  new systems unless needed for a found gap).

## Strategy

1. Extend the observation DSL with richer fact types so the harness captures
   more of what vanilla/solaris produce per scenario.
2. Write 2-3 new deterministic scenarios that exercise currently unverified
   gameplay paths.
3. Run against vanilla oracle where `.analysis/server.jar` exists; record
   diffs.
4. Triangulate each mismatch: write failing regression, fix root cause, verify.
5. Refresh replacement readiness.

## Risks

- Vanilla oracle availability is sporadic; keep non-ignored CI gates
  independent of the jar.
- New observation facts may make diffs noisier; normalize carefully and
  document intentional differences.
- Parity fixes risk scope creep; fix only what the oracle finds, defer
  systematic rewrites.
