# Physics Oracle Workflow

M43 uses local vanilla 26.1.2 captures as evidence for physics validation. Captures
are local artifacts only and must stay under `.analysis/physics-oracles/` or another
gitignored path.

## Inputs

- Vanilla server jar: `.analysis/server.jar`.
- Protocol dump: `.analysis/protocol-dump.txt`, generated by
  `tools/dump-vanilla-protocol.sh` from `javap` output.
- Solaris config: `example.toml`, using local `data/vanilla/` sidecars.

## Start Servers

Vanilla 26.1.2 oracle server, from the workspace root:

```sh
mkdir -p .analysis/vanilla-physics-server .analysis/physics-oracles
printf 'eula=true\n' > .analysis/vanilla-physics-server/eula.txt
(cd .analysis/vanilla-physics-server && \
  java -Xms1G -Xmx1G -jar ../server.jar --nogui --world physics-world)
```

Solaris comparison server, from a second shell:

```sh
RUST_LOG=info cargo run --bin mc-server -- --config example.toml
```

Use offline mode and the same deterministic scenario setup on both servers. Do not
commit generated worlds or captures.

## Capture Format

`wire-probe` writes a text capture with this header:

```text
# solaris-wire-capture-v1
scenario=<stable scenario name>
server_kind=<vanilla|solaris>
addr=<host:port>
player=<login name>
protocol_version=<numeric protocol version>
play_seconds=<seconds>
captured_at_unix_ms=<local timestamp>
packet_source=.analysis/protocol-dump.txt or javap net.minecraft.network.protocol.*
```

Frame lines keep the existing raw probe shape:

```text
[PLAY] id=0xNN body_len=<bytes> body=<short hex prefix>
[PLAY->SERVER:<packet name>] id=0xNN body_len=<bytes> body=<short hex prefix>
```

Committed tests should cite either this local capture path or the `javap` class / dump
section that established the packet ID and field layout. The capture file itself is
not committed.

## Commands

Spawn burst smoke capture:

```sh
cargo run -p mc-test-harness --bin wire-probe -- \
  --addr 127.0.0.1:25565 \
  --server-kind vanilla \
  --scenario spawn-burst \
  --play-seconds 5 \
  --out .analysis/physics-oracles/spawn-burst.vanilla.capture
```

Solaris comparison capture:

```sh
cargo run -p mc-test-harness --bin wire-probe -- \
  --addr 127.0.0.1:25565 \
  --server-kind solaris \
  --scenario spawn-burst \
  --play-seconds 5 \
  --out .analysis/physics-oracles/spawn-burst.solaris.capture
```

Named M43 scenarios use the same command shape with these stable names:

- `player-shallow-water-entry`
- `player-deep-water-swim`
- `player-water-surface-exit`
- `entity-land-passive-motion`
- `entity-hostile-motion`
- `entity-aquatic-motion`
- `item-water-drop-window`
- `sugar-cane-support-break`
- `sand-gravel-fall-start`
- `farmland-trample-fall-edge`
- `water-lava-replacement`
- `collision-wall-step-fall`

`player-shallow-water-entry` is scripted by `wire-probe`: after Play start it
confirms the spawn teleport, sends movement into the fixture pool, starts
sprinting, sends forward+jump+sprint input, then records post-input Play frames.
The serverbound lines in the capture are part of the oracle and should be cited
with the corresponding clientbound metadata, motion, or correction frames.

`sugar-cane-support-break` currently has a Solaris harness observation on the
M43 deterministic fixture: creative break of support dirt at `(8, 63, 0)` must
emit a target flowing-water replacement (`minecraft:water[level=1]`) and matching
`BlockChangedAck`. This is backed by the external vanilla harness gate:

```sh
M43_VANILLA_ADDR=127.0.0.1:25566 \
  cargo test -p mc-test-harness --test physics_validation \
  external_vanilla_sugar_cane_support_break_oracle -- --nocapture
```

Sugar cane cascade timing and drops still need vanilla capture before they become
assertions.

## Comparison Rule

Each assertion must be labelled as one of:

- `exact`: packet or state must match the vanilla observation.
- `tolerance`: timing or position is compared with an explicit bound.
- `deferred`: captured but intentionally not asserted in M43.

M43 may record Solaris mismatches, but broad physics fixes belong to M44.
