# Solaris v0.0.5

Preliminary release for Minecraft Java Edition **26.1.2**. Maturity remains
**draft**: these are implementation and native-regression fixes for owner field
testing, not a claim of production readiness or completed graphical acceptance.

## Changelog since v0.0.4-alpha.1

### Player movement, damage and respawn

- Reject block placements whose collision shapes intersect the placing player.
  Rejected non-positional player-pose updates restore the accepted pose instead
  of disconnecting the player.
- Sprinting into shallow water no longer starts swimming unless the eyes are
  already submerged, avoiding unintended oxygen bubbles while wading upright.
- Drowning and suffocation now require water or solid contact at both feet and
  eyes. This is an intentional owner-requested behavior change, not a claim of
  exact vanilla parity for eyes-only submersion.
- Respawn chunk replay first switches to the respawn location rather than
  replaying the death location's view.

### Animals and aquatic populations

- Bound natural admission to 10 ground animals, 20 aquatic mobs and 70 hostiles.
  Admit at most two ground animals per chunk to spread new populations out.
- Limit the water-creature category, including ordinary squid and dolphins, to
  five within the aquatic total, leaving more capacity available for fish.
- Consider loaded client chunks within 128 blocks for natural spawning,
  independently of a smaller AI simulation distance. Aquatic candidates are no
  longer restricted to four chunks when the loaded view extends farther.
- Shorten wandering pauses. Injured wandering animals preserve the initial
  impulse, then run at increased speed for up to five seconds.
- Send the hurt event on accepted nonlethal attacks and correct melee knockback
  from per-tick impulses to the runtime's blocks-per-second velocity units.

Existing animals are preserved, not retroactively culled. AI activity still
obeys simulation distance; spawning farther away does not expand that budget.

### Mining and memory

- Allow mining to complete across property changes of the same block, such as
  leaf-distance updates. Track the last different-type replacement revision so
  leaves replaced through air or stone cannot inherit an older mining request.
  Exact current state/version checks still protect the owner commit.
- After successful persistence, trim clean chunks outside retained client views
  to a 64-chunk warm cache. Loaded and dirty chunks are not discarded. This and
  population admission bounds address accumulation; a measured gameplay RSS
  improvement is not claimed yet.

### Hosting, logging and profiling

- Permit public offline-mode listeners with an explicit impersonation warning.
  The starter configuration now listens on `0.0.0.0`. Public local-development
  operator grants remain forbidden; authenticated online mode is recommended.
- Write runtime tracing to `logs/latest.log` and `logs/debug.log` instead of
  streaming it into the console. Logs start fresh on server launch; `--check`
  and `operator` subcommands leave existing server logs untouched. `RUST_LOG`
  controls the debug file's filter.
- Add the local console command `profile`, exporting measured tick-stage latency,
  memory, population, chunk and network metrics to `logs/profile.json`. This is
  a runtime metrics profile, not CPU stack sampling or an allocation trace.
- Preserve captured readiness logs for canonical harness runs through their
  explicit `SOLARIS_HARNESS_LOG_STDOUT=1` subprocess environment.
- Include this changelog as `CHANGELOG.md` in both Linux release archives.

## Upgrade notes

Back up the world and configuration before upgrading. Existing configuration
files are not rewritten: choose the appropriate public interface and configure
firewall/NAT forwarding yourself. Offline-mode player and operator identities
can be impersonated; do not expose an untrusted offline server.

This release does not introduce another world-contract migration relative to
alpha-4. The alpha-3-to-alpha-4 world-contract boundary still applies: older
Solaris contracts require a fresh world directory rather than bypassing their
compatibility check. Loader and first-party plugin sources remain independent
repositories; the core production binary does not require them.

## Validation boundary and known gaps

- The local release-candidate workspace test run passed **4,475 tests**, with
  **194 ignored**. Formatter, strict Clippy, code-health, installer and harness
  checks also passed. Ignored tests are not gameplay or parity evidence.
- Native regressions cover self-placement, shallow and full-body submersion,
  animal panic, spawn limits/distance, interrupted leaf mining and saved-chunk
  eviction. A live debug-server smoke exercised public offline listening,
  file logging, log preservation, profile export and clean shutdown.
- The release workflow gates assets on formatter, strict Clippy, code-health,
  workspace tests, build, Loader checks and installer validation, then performs
  target-native archive/version/config smoke checks and publishes SHA-256 files.
- Graphical owner acceptance, public internet online-login acceptance, vanilla
  oracle recapture and gameplay performance comparisons are **not run** for
  these changes. Online-authentication cryptography itself was not changed.
- The Lua gameplay-event integration test timed out in earlier parallel runs
  and subsequently passed focused and full-scope execution. Its intermittent
  root cause remains unestablished; no assertions or timeouts were relaxed.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/kaiserproger/solaris/v0.0.5/install.sh | \
  SOLARIS_VERSION="v0.0.5" bash
```

Linux x86_64 and AArch64 archives contain the server, starter configuration,
README, changelog, version marker and licenses. Pin `v0.0.5`: GitHub's `latest`
alias does not select a prerelease.
