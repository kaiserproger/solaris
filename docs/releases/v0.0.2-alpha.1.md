# Solaris v0.0.2-alpha.1

Solaris `v0.0.2-alpha.1` is the second public alpha for Minecraft Java Edition 26.1.2.
It is still an alpha server engine: use it for testing, development servers, plugin
experiments, and bounded multiplayer sessions rather than production replacement.

## Highlights since v0.0.1-alpha.1

- Much broader ordinary-survival coverage: natural resources, crafting, containers,
  food, sleep, combat, death/respawn/drop recovery, weather/time, persistence, and
  two-client authority paths have executable production evidence.
- Common entity/AI work now covers villagers, village defence, guardians, common
  passive/hostile populations, navigation, combat, despawn, drops, restart identity,
  and additional hostile species/boss-specific bounded behavior.
- Natural spawning is a periodic regional runtime rather than one-shot chunk
  decoration, with category caps, loaded-chunk/player-distance fences, darkness and
  support checks, metrics, and restart-safe retained entities.
- Server-owned Luau plugins now have a production API foundation: typed/correlated
  world-time, block, entity-spawn and entity-damage mutations, capability checks,
  safe reload/lifecycle diagnostics, durable storage, commands, menus, zones,
  timers, inventory/economy adapters, and stronger mutation-authority fencing.
- Solaris Loader compatibility now has explicit deployment reporting and live
  Fabric/NeoForge/Forge compatibility gates, exact bundle identities, permission
  prompts/cache behavior, and clear no-Loader rejection for client-required content.
- Network/runtime hardening added bounded pre-Play/Play admission, strict frames and
  configuration bodies, liveness validation, bounded simulation/script waits,
  fail-stop regional-owner behavior, storage-pressure recovery, and safer atomic
  persistence replacement.
- Crate ownership was tightened: protocol-independent domain values and substantial
  item, placement, inventory, combat, survival/mining, recipe, merchant, movement,
  chunk-stream and spawn semantics moved below `mc-net`, with code-health tripwires.
- Test infrastructure was hardened and made deterministic: aggregate `mc-net` test
  ownership was split into focused modules, wall-clock/yield polling was removed from
  first-party test/gate synchronization, and active-feature debug loops now name exact
  unit/TCP/restart/real-client continuations.
- Release-2 evidence includes a full 24,000-tick fresh-world no-operator survival
  session with natural passive+hostile observation, three death/recovery cycles, and
  clean restart/rejoin, plus the 200-action break/drop/pickup latency gate.

## Release boundary

All automated `v0.0.2-alpha.1` gates are green. The owner chose to defer the
subjective terrain/playability judgement for `tellus_like` seed `712816` to
`v0.0.3-alpha.1` rather than block this release or misreport it as a PASS. The
prepared screenshots/mosaics remain available in the repository and the carry-over
is recorded in `docs/PUBLIC_ALPHA3_PLAN.md`.

Full vanilla parity is still not claimed. Remaining rare/species-specific parity,
longer performance envelopes, and any worldgen changes resulting from the deferred
owner review belong to later alphas.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/kaiserproger/solaris/main/install.sh | \
  SOLARIS_VERSION="v0.0.2-alpha.1" bash
```

Starter config:

```sh
curl -fsSLo server.toml \
  https://raw.githubusercontent.com/kaiserproger/solaris/v0.0.2-alpha.1/example.toml
solaris --check --config server.toml
solaris --config server.toml
```

The GitHub release workflow publishes SHA-256-verified Linux x86_64 and AArch64
archives after the tagged commit passes formatting, Clippy, code-health, workspace
tests, build, Loader checks, installer validation, target-native release builds and
archive smoke tests.
