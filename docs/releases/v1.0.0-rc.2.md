# Solaris 1.0 "Pauline" RC2

Release candidate 2 of Solaris 1.0. It fixes the owner playtest findings on RC1
and makes the native client look like vanilla Minecraft by default. Same target
as RC1: Minecraft Java Edition **26.3** (protocol 777); 26.1.2 (775) clients can
still join. Existing RC1 worlds keep working.

**Upgrading from RC1:** run `solaris-v2 content import --version 26.3 --download`
once more. RC2 needs the English language file in the content cache (for
console translations), which the RC1 import did not copy. On an RC1 cache the
server stops at startup with "no vanilla content cache found".

## Server

- Player list ping is the real, smoothed keepalive round trip instead of 0.
- A refused door use (spawn protection, claims) resends both door halves
  before the block acknowledgement, so the client never keeps a half-open door.
- Villagers:
  - at night, bound residents without a roofed bed of their own (nitwits, the
    unemployed, children) shelter in a free roofed cell beside a settlement bed,
    one per cell; residents with a roofed bed sleep in it;
  - resting or idle residents sit on a nearby roofed bottom stair with headroom,
    shown to every client as a passenger on an invisible seat (never saved);
  - children's nameplates say `ребёнок` until they grow up;
  - a lumberjack drops a tree it cannot reach instead of holding it forever.
- **Projects** lists each missing material with stock/needed, an example source
  ingredient and why it is not coming (`Oak Planks 0/26 — needs, e.g. Oak Log —
  no lumberjack`).

## Native client

- The default graphics preset is now **Low**, the vanilla-like path. Grass,
  wood, stone, night darkness, water and underwater fog closely match vanilla
  in side-by-side samples; Medium and High (HDR, bloom, shadows, god rays) stay
  available in Options.
- Clouds, the targeted-block outline, torch flame and smoke, the darkness
  vignette, vanilla-like hotbar and crosshair; creative and spectator hide
  health and hunger; F1 hides the HUD.
- Models refit against the vanilla client: bell, single and double chests, iron
  golem, child villager, villagers lying in bed, seated villagers; soft
  shadows under entities; server text displays (e.g. house occupancy) render.
- Render distance up to **32**. The terrain mesh scheduler no longer stalls:
  at 32 chunks the first load drains in about 100 s instead of over 7 minutes,
  and frame time drops by about a third (measured on an intermediate build,
  High preset, under Xvfb). Blocks placed in empty sky sections appear
  immediately.
- Far terrain stays until the near terrain under it has meshed, so no sky holes
  or floating LOD shelf at the near/far boundary.
- Opening a door predicts both halves, so a door you opened can be walked through
  at once.
- F10 sends a frame profile after a session.

All models and values are our own: fitted to observations of the vanilla client
and loaded game resources, not copied from Mojang code or data.

## Validation

- Core: strict workspace Clippy and all 6810 workspace tests (L2).
- Client: 805 library tests plus the launcher and integration suites.
- Real-client gates with the windowed native client: `survival` and
  `title-connect` pass; side-by-side comparison with the vanilla 26.3 Java client
  on bell, chests, golem, villagers, sleeping, doors, water at night and the
  32-chunk far view.

## Known issues

- `village-autonomy-qa`: an ownerless village builds its first Storage, but no
  second completed building and no completed upgrade were verified within the
  gate's 25-minute pre-claim window. Production works (stock accumulates in
  Storage); whether a second project was admitted, funded or in progress is
  not yet known.
- Cloud pattern and torch particle timing differ slightly from vanilla. Shallow
  underwater floors are slightly brighter than vanilla.
- Strict Clippy for the client crate still reports the known lint backlog.
