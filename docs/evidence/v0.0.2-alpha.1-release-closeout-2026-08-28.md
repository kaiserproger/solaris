## Native AArch64 Luaur portability fix

The next tag run (`33147074930`) passed the complete pre-release matrix, including the Loader job above, and entered both native release jobs. The native `ubuntu-24.04-arm` job then failed compiling crates.io `luaur-vm 0.1.8`: the translated Luau Rust source used hard-coded signed `i8` at C `char` boundaries, while Linux AArch64 defines Rust `core::ffi::c_char` as `u8`. The failure was compile-time `E0308`/signedness mismatch, not a Solaris runtime assertion.

Solaris keeps the same Luau static-checking contract on both architectures rather than disabling `luaur::check` on ARM. A public fork at `kaiserproger/luaur` carries the portability patch on the exact published `luaur 0.1.8` source commit `f0eac7f7cce691d0cdb0b93c3eef9d599f71d739`. Solaris pins exact fork revision `ea648bd95d4948b47dd66e5df62074b5b7ef2ec7`.

The fork differs from the published 0.1.8 `src/` trees in exactly 24 files: eight `luaur-vm`, five `luaur-ast`, two `luaur-compiler`, and nine `luaur-analysis` files. The changes only replace translated `i8` character buffers/literals or pointer boundaries with platform `c_char` (plus one byte-hash pointer cast); no VM/typechecker algorithm or public Luaur API is changed. Source comparison explicitly rejected unrelated unreleased upstream drift before the clean fork commit was created.

Portability validation on the clean release-base fork:

- `cargo +1.94.1 check -p luaur --target aarch64-unknown-linux-gnu` — PASS;
- `cargo +1.94.1 check -p luaur` — PASS;
- `cargo +1.94.1 test -p luaur-vm -p luaur-ast -p luaur-compiler -p luaur-analysis --lib` — PASS (including VM 22/22 and AST 144/144; command exit 0);
- Solaris `cargo check -p mc-server` with the pinned revision — PASS;
- Solaris `cargo test -p mc-script --features lua-runtime` — 202/202 PASS.

A local full Solaris AArch64 cross-check proceeds through the patched Luaur packages and then stops in `aws-lc-sys` because this x86_64 workstation does not have the external `aarch64-linux-gnu-gcc` cross C compiler installed. This is an environment boundary, not accepted as the authoritative ARM release proof. The GitHub release workflow uses a native `ubuntu-24.04-arm` runner, where the next tagged build remains the required full AArch64 compile/package/smoke gate.
